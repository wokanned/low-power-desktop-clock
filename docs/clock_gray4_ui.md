TEMP/BAT、WIFI/内存四格；分隔线 x=160、228。温度计、电池、Wi-Fi 和空心圆环

### 实机照片对应的可读性修复

2026-10-18 的照片中，主时间较完整，日期与四格小字笔画断裂。源码检查发现旧小字
经过四倍超采样缩小、窄体压缩后，部分字形位图宽度还大于字符推进距离。
相同照片数据的旧 C 帧中，日期50.29%、标签53.37%至56.62%的非白像素为灰色；
新正常页小字及信息图标只使用白/黑，避免细笔画依赖尚未校准的物理灰度表现。
这修正字形和字距问题，照片本身不能证明控制器的真实四级灰度有故障。

`build/clock-aligned-host/`保存实际C渲染的照片同数据、最长日期和三种内存页面，
以及1:1和整数放大的旧新对照。black-only软件消融图只移除旧帧灰色像素，
用于暴露旧字的实黑骨架，不是实机灰度或屏幕效果模拟。

主时间的旧比例字宽使`11:11`仅94px，`04:44`达144px，分钟起点随小时变化。
固定格修复这一漂移，并通过原生字号栅格化和微增字重优化分钟笔画。

四灰阶原生帧为128x296、9472字节，2bpp MSB first，0=白、3=黑。逻辑坐标映射：

```text
native_x = 127 - y
native_y = 295 - x
byte = native_y * 32 + native_x / 4
shift = 6 - 2 * (native_x % 4)
```

黑白原生帧为128x296、4736字节，1bpp MSB first，1=白、0=黑。沿用上述坐标，
字节地址为`native_y * 16 + native_x / 8`，位号为`7 - native_x % 8`。
两种格式共用布局代码，直接绘制到目标缓冲，无中间灰阶帧或运行时缩放。
现有9472字节静态缓冲继续供可选四灰阶页面及互斥演示使用；默认黑白时钟和天气页绘制前4736字节，后半缓冲复用为局刷窗口的紧排数据，不新增整帧缓冲或动态分配。

## 模型、任务与刷新

`clock_view_model_t` 是纯值快照。`UNAVAILABLE`、`ERROR` 字段显示 N/A，只有
READY数值可展示。2026-10-28起W25Q使用文件系统快照，检查中和未格式化显示N/A；物理扫描不再驱动SCAN，绘制器保留原INITIALIZING字模以兼容历史测试。当前TEMP/BAT没有提供者，
不创建虚假的正常值或故障。WIFI接入USART2成功同步记录，规则见下文。ADXL345 不支持温度，不把其 temperature-invalid 位报为 TEMP。

defaultTask 通过 `clock_service_run()` 每秒读取完整 RTC 日历，每十秒缓存内存统计；星期由公历日期计算。TIME 请求通过静态邮箱和任务通知提前唤醒该所有者，一秒轮询截止时间不随校时请求推迟。
RTC 读取先 Time 后 Date，失败也尝试释放 shadow 锁。备份标记只代表初始化，
备份域首次初始化或失电后为 `2000-10-18 00:00:00`，未校准的默认日历仍正常显示。
普通复位在备份域供电保持时保留日历；USART2 可通过 [TIME 命令](time_protocol.md)校时，NTP 尚未接入。天气消息的
时间仅作标签，不设置 RTC。RTC 读取/范围失败进入 RTC 类，顶栏为 --:-- / N/A，
不会令显示传输重试或挂起。

TIME 在一次 INIT 中写完整日期时间，退出同步并读回成功后才发布新快照；允许正常前进一秒。写入或验证失败会锁存 RTC 不可信状态，普通合法读数不会自行清除此状态，下一次完整校时成功才恢复 READY。校时只更新当前故障时间锚点，历史记录不改写；改变日期、分钟或可见 WIFI 状态/整小时值会触发刷新，同一分钟只改秒且 WIFI 显示不变时不刷。

`WIFI` 沿用现有标签，表示距上次成功同步的时间：完整有效 WEATHER 提交后调用任务接口 `clock_service_note_sync_success()`，重复有效包同样归零；TIME 仅在 RTC 写入、同步和读回验证全部成功后，于发布时钟模型的同一临界区记录成功。接口在同一短临界区采样单调 tick、记录成功并将 `wifi` 置为READY/0；每秒服务同样在采样tick的临界区维护整小时，支持当前32位tick回绕。启动无记录显示 `N/A`；成功显示 `0h ago`，满一小时显示 `1h ago`；达到100小时锁存为 `99h+`，直到下一次成功。记录仅存RAM，后续失败保留，重启清空；RTC前后调整和天气来源时间不作为计时依据。

默认静默模式与控制台模式都会记录，应答发送失败不撤销成功。仅接受请求、参数错误、忙拒绝、RTC失败、PAGE、FORMAT、文件维护和普通串口流量不计入。正常时钟页将Wi-Fi可见状态和整小时值纳入刷新判断，`N/A→0h ago`、小时变化及非零小时重新归零及时更新，同小时重复零小时不追加刷新。天气/故障页隐藏字段时不因此刷新；BUSY期间合并最新模型，返回时钟页显示最新值。该记录不新增联网、信号强度或断线判断。可直接发送的逐行验收示例见[天气协议](weather_protocol.md#wifi-同步记录与验收示例)。

`clock_fault_report()` 由生产者在任务上下文报告，快照在短临界区复制。
来源保存 active/first 原因、首次 tick、首次完整日历和有效标记；类别保存整次
类别故障的首次时间。相同原因重复报告不修改修订号和时间。类别部分恢复不改
首次时间，完全清除后再次发生建立新记录。可用 RTC anchor 不超过两秒，按
单调 tick 补足秒数；失效时不伪造发生时间。已恢复来源的最近一次记录保留在 RAM，
不跨复位持久化。

2026-10-28起，`clock_faults_get_snapshot()` 保留完整诊断，`clock_service_get_model()`
使用独立的显示故障快照。显示快照只排除DBG来源的TX位，独立维护修订号、类别及首次时间。
串口发送失败及恢复均不触发全刷，也不覆盖时钟或天气页；ERRORS和累计错误计数继续保留记录。
RX、溢出、TASK、RTC及存储等故障沿用原上屏规则。

固定七类 RTC/TEMP/BAT/WIFI/SENSOR/STORAGE/SYSTEM；SENSOR 合并 IMU/BARO/LIGHT，
STORAGE 合并 W25Q/CFG，SYSTEM 合并 TASK/DBG。七行字号14、行距14，顶栏同时
放置小时间、日期和星期。单一来源显示简短原因，多个来源列出来源；完整掩码和
各自发生时间由 ERRORS 输出。错误时间及错误页顶栏使用24h，正常页可切12h并显示AM/PM。
EPD 故障不进入屏幕类别；停机异常没有新增崩溃恢复或持久化报告。

首刷等待时钟服务首次轮询和存储配置终态，不等待文件分区空白检查或后续容量扫描。当前
`STORAGE_BOOT_TEST_ENABLE=0`，正常启动不擦写自检区；显式 `FS SELFTEST CONFIRM` 才操作
`0x0000F000..0x0000FFFF` 专用4KiB区。保留分钟更新；正常时钟页可见WIFI状态/整小时变化仍触发刷新。
首帧、切页、日期/时制/天气内容/故障变化、异常恢复及允许局刷区域外的像素差异走全刷。
RTC不可用且其他状态不变时不重复刷相同错误页。
刷新期间合并变化，成功后只检查最新模型，不补播历史帧。

默认黑白连续显示先以原厂BW_296初始化全刷建立背景：4736字节图像写入24并同步26旧图RAM，
F7激活后等待BUSY完成。同页按下表范围与最后成功图像比较，按实际差异收紧窗口，转换到
控制器坐标并按8像素对齐；扩展部分复制完整新帧像素，不能刷白。时钟页先时间、后内存格
分别激活局刷，未变化的窗口跳过；天气页最多一个时间窗口。区域外出现差异则整轮全刷。

`epd_bringup_get_refresh_stats()`提供驱动已确认BUSY成功的全刷、快刷、局刷及自上次全刷以来的计数；已激活但超时的操作不计成功数。
`EPD_CLOCK_USE_GRAY4=1`仍使用原厂GRAY4初始化、
9472字节转换为24/26两平面和C7激活，再等待BUSY、提交和sleep。

## 内存与配置

SRAM 显示“已分配/保留”，分母131072字节：

```text
linked = sum(Image$$RW_IRAMn$$ZI$$Limit - Image$$RW_IRAMn$$Base)
used = linked - xPortGetFreeHeapSize()
```

静态栈/帧缓冲、启动栈和C heap保留空间均已包含；RTOS堆数组在linked中，
因此动态TCB/栈不能再次相加，也不减stack high-water。两块非连续SRAM逐region求和。
IFLASH 分母524288字节，统计 `Load$$LR$$LR_IROM1$$Limit - Base`，包含压缩后的
RW初值与实际加载区开销。链接器符号只取地址，不解引用。百分比四舍五入。
W25Q使用 `storage_get_files_snapshot()` 的RAM快照，不在显示或时钟服务中读Flash。只接受总块数3070且已分配块数不超过总量的READY快照，容量向上取整，非空最低1%；格式化后元数据本身也占空间。未就绪/未格式化显示N/A，文件错误显示N/A并聚合STORAGE故障。物理全片扫描保留为独立诊断，每轮结束1小时重扫；其非空扇区数包含残留内容，不能替代文件容量。容量变化不额外触发刷新、不阻塞首刷，沿用分钟刷新和SRAM/IFLASH/W25Q轮换。详情见[文件系统](filesystem.md)。

24h默认、12/24格式配置由storageTask独占的静态请求队列保存。双独立4KiB扇区
0x00FFE000、0x00FFF000，避开既有0x0000F000启动测试区。提交算法、损坏恢复及
保留的破坏性自检见 `w25q128_storage.md`。串口显式控制台协议见 `debug_console.md`。
