# USART2 天气输入与页面切换

更新日期：2026-10-28。文档入口见 [文档导航](README.md)，工程状态见 [totalPLAN.md 的当前开发状态](totalPLAN.md#当前开发状态2026-10-27)。

当前固件通过 USART2 接收深圳或湛江的完整天气数据，在 RAM 中保留最新一份记录。时钟页和天气页每三分钟自动切换，收到完整有效的 `WEATHER` 命令后立即选择天气页，并重新开始三分钟计时。串口 `PAGE` 命令仍可手动切页。天气来源更新时间只用于显示；设置 RTC 使用独立的 [TIME 校时命令](time_protocol.md)。ESP32 联网、自动获取天气和 NTP 校时尚未接入。

## 连接、编码与长度

使用 H10 的 USART2 调试串口，TX 为 PA2，RX 为 PA3，电平为 3.3V TTL。串口助手设置为 115200 波特率、8 数据位、无校验、1 停止位，发送编码选择 UTF-8。

发送端 TX 接 STM32 PA3，发送端 RX 接 PA2，双方共地。板载 ESP32-C3 原连接 USART1，当前业务尚未接入；外部 ESP32 使用本协议测试时需连接 H10。

命令区分大小写，每条命令占一行，以实际 CR、LF 或 CRLF 结束。串口助手可设置自动添加 CRLF，即字节 `0D 0A`；不要把字符 `\r\n` 当作行结束符发送。

- `WEATHER` 整行最多 127 字节，包含命令、空格、城市和全部字段，不包含行结束符和终止 NUL。长度按 UTF-8 字节计算；“深圳”和“湛江”均占 6 字节。
- 其他命令保留原来的 31 字节上限。
- 只有精确的 `WEATHER` 后接空格或逗号的命令族允许使用长行。`WEATHERX` 等前缀不享受例外；有效天气包仍必须使用下文的 `WEATHER ` 加九字段格式。
- 损坏的 UTF-8、禁止的控制字节、超长行或硬件接收错误会丢弃当前整行，遇到行结束符后恢复收行。

## 串口助手发送示例

逐行发送以下命令。进入控制台后，每行等待对应应答再发送下一行。

```text
CONSOLE ON
WEATHER 深圳,2,235,180,270,65,2,35,2026-10-28T14:30
```

预期应答依次为：

```text
OK CONSOLE ON
OK WEATHER
```

示例表示深圳、多云、当前 23.5°C、最低 18.0°C、最高 27.0°C、湿度 65%、东北风 3.5m/s，来源更新时间为北京时间 2026-10-28 14:30。`WEATHER` 校验成功后会同时更新缓存、选择天气页并重新计时，不必再发 `PAGE WEATHER`。应答只确认接收或页面请求成功，屏幕刷新可能仍在进行。此后三分钟没有新的有效天气命令或手动切页，就切到时钟页；再过三分钟切回天气页，持续循环。

确认天气页刷新完成后，如需提前返回时钟页并恢复二进制遥测，再逐行发送下面两条命令，分别等待 `OK PAGE CLOCK` 和 `OK CONSOLE OFF`。手动切页会从该命令重新计时，三分钟后切回天气页。只想恢复遥测并保留天气页时，单独发送 `CONSOLE OFF` 即可，它不改变轮换计时。不要把进入与返回时钟页的示例整块连续发送，否则显示任务可能合并中间的切页请求。

```text
PAGE CLOCK
CONSOLE OFF
```

湛江静风示例：

```text
WEATHER 湛江,1,286,220,310,72,0,0,2026-10-28T14:35
```

这会用湛江记录替换此前深圳记录，并选择天气页、重新开始三分钟计时。默认 JustFloat 模式也接收 `WEATHER` 和 `PAGE`，行为相同，但不输出文本应答。`CONSOLE ON` 暂停遥测并开启应答；`CONSOLE OFF` 成功后恢复遥测。控制台完整约定见 [debug_console.md](debug_console.md)。

## WEATHER 九字段格式

```text
WEATHER 城市,天气码,当前温度,最低温度,最高温度,湿度,风向码,风速,来源更新时间
```

字段顺序固定，必须一次发送全部九个字段，不接受字段前后空白、引号、转义、部分更新或额外字段。首版协议不含 CRC。

| 序号 | 字段 | 格式与约束 |
| --- | --- | --- |
| 1 | 城市 | 精确匹配 `深圳` 或 `湛江` |
| 2 | 天气码 | 整数 0～13，含义见天气码表 |
| 3 | 当前温度 | 整数 −999～999，单位为 0.1°C |
| 4 | 最低温度 | 整数 −999～999，单位为 0.1°C |
| 5 | 最高温度 | 整数 −999～999，单位为 0.1°C，必须不低于最低温度 |
| 6 | 湿度 | 整数 0～100，单位为 % |
| 7 | 风向码 | 整数 0～8，含义见风向码表 |
| 8 | 风速 | 整数 0～999，单位为 0.1m/s；静风码 0 必须配合风速 0 |
| 9 | 来源更新时间 | 北京时间 UTC+8，严格使用 `YYYY-MM-DDTHH:MM`，年份 2000～2099，日期必须真实有效 |

温度和风速传整数十分之一单位，不直接发送小数。例如 `235` 表示 23.5°C，`-35` 表示 −3.5°C，风速 `35` 表示 3.5m/s。数值不接受 `+` 正号；只有温度允许负号。时间字段月份、日期、小时和分钟必须补足两位，小时为 00～23，分钟为 00～59，并检查闰年。

全部字段校验通过后才一次性替换完整天气记录、选择天气页并重新计时。任何字段无效，都保留此前数据、过期计时和页面轮换计时；接收损坏或超长行也不会触发天气切页。

## 模式与应答

默认 JustFloat 模式下，`WEATHER` 和 `PAGE` 的成功、内容错误及接收错误均不输出文本。控制台模式下使用以下应答：

| 应答 | 含义 |
| --- | --- |
| `OK WEATHER` | 完整天气数据校验成功，已更新 RAM 缓存、选择天气页并重启三分钟计时 |
| `OK PAGE WEATHER` | 天气页选择请求已接受，三分钟计时重新开始 |
| `OK PAGE CLOCK` | 时钟页选择请求已接受，三分钟计时重新开始 |
| `ERR WEATHER` | 天气命令内容无效，旧缓存、过期及页面计时保持不变 |
| `ERR RX` | 当前行存在接收错误、损坏 UTF-8、禁止控制字节或长度超限，整行丢弃 |
| `ERR COMMAND` | 未识别的命令文本 |

`WEATHER` 和 `PAGE` 不受在途 `FORMAT` 持久化事务或 `TIME` 校时事务阻塞。`OK PAGE WEATHER`、`OK PAGE CLOCK` 和 `OK WEATHER` 均不表示墨水屏已经刷新完成。系统故障页覆盖画面时，自动轮换和命令继续更新目标页面及其计时，故障清除后返回最终目标页面。

## 缓存、过期与显示刷新

天气、选中页面和轮换计时都只存在 RAM 中。重启会清空天气并选择时钟页，重新开始轮换。即使尚未收到天气，三分钟后也会切入天气页，显示“等待天气数据”和数值占位符；再过三分钟返回时钟页。

每个完整有效的 `WEATHER` 包都会选择天气页，并从接收成功时重新计三分钟，相同的重复有效包也一样。`PAGE CLOCK`、`PAGE WEATHER` 手动选择目标页，并重新计三分钟；请求当前已选页面也会重新计时。其他命令不重置此周期。轮换使用单调 FreeRTOS tick，支持当前 32 位 tick 回绕，不受 `TIME` 前后校时或天气来源时间影响。

三分钟是页面选择周期，实际画面完成切换还要等待显示任务调度和墨水屏刷新。BUSY 期间只保留最新目标。若较长延迟跨过轮换截止点，恢复检查时只切一次，并从当时重新计三分钟，不补播中间页面。

每个完整有效包都会重新开始三小时有效期，重复有效包也一样。连续三小时未收到有效包后，保留旧数据并显示“已过期”。过期计时使用单调 FreeRTOS tick，处理当前 32 位 tick 回绕；过期状态保持到下一份有效包到达。来源时间和 `TIME` 对 RTC 的调整均不影响这个计时。

天气页分辨率为 296×128，显示城市、过期标志、RTC 小时钟、天气图标和中文描述、大号当前温度、最高最低温度、湿度、风向、风速，以及来源更新的月日时分。小时钟沿用 12/24 小时配置，12 小时制显示 AM/PM，不显示秒。

切页、可见天气内容变化和 RTC 分钟变化会请求全刷。来源更新时间变化属于可见变化。天气页已选中时，相同数据只重启轮换及过期计时，不因此重复刷新；时钟页选中时，即使收到相同数据，也会请求切到天气页。刷新期间只保留最新快照，并与上一个已完成画面比较；若 BUSY 期间数据由 A 变为 B 又恢复 A，且 A 与上一个已完成画面相同，就不再重复刷新 A。

故障沿用整屏故障页，故障恢复后返回最终选中的页面。显示任务独占绘图和刷新，BUSY 完成后才提交已显示版本；天气帧不推进时钟页的内存格轮换。墨水屏控制器完成刷新后休眠，不代表 MCU 已进入 STOP2。

生产默认配置为 `EPD_VENDOR_DEMO_MODE=0`、`EPD_CLOCK_USE_GRAY4=0`，采用黑白全刷。代码保留四灰阶构建兼容性；主机灰阶测试通过不代表四灰阶实屏验收通过。

## 来源时间与 RTC 校时

`WEATHER` 最后一个字段是发送端天气记录的来源更新时间，只用于天气页页脚显示。即使它早于或晚于当前 RTC，也不会校时或改变三小时有效期。

需要设置时钟时，另发北京时间整秒，例如：

```text
TIME 2026-10-28T14:30:00
```

实际发送时应换成发送当时的真实北京时间，不能直接把天气来源时间作为当前时刻。TIME 的异步应答、失败恢复及验证范围见 [time_protocol.md](time_protocol.md)。

### 当前布局与视觉改造目标

当前天气渲染仍使用16×30七段大数字、16×16中文和多行完整字段标签。主温度有℃，高低温尚未显示°，风速尚未显示m/s，阅读时需结合本协议单位。数字、小数点及℃的位置随位数和负号变化。主机测试通过只证明这些现有行为，不代表已实现此前选定的视觉稿。

下一轮按已选的图标分栏和28×40圆弧字形改造，统一原生小字、固定动态位置、补足单位，精简为“待更新”“过期”等短标签，并区分未知/无数据图标。当前实现与目标图、坐标及验收方法见[墨水屏显示效果优化](epd_display_quality.md)。这些视觉改造仍待实施；本轮只增加轮换和天气包切页，不改变九字段格式、三小时过期或应答文本。
