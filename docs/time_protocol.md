# USART2 校时与亚秒读回

[多天预报](forecast_protocol.md)复用本命令：每个新批次须先取得一次`OK TIME`，STM32按成功结果授予一次接收许可。收集或保存预报期间TIME返回BUSY。预报日期决定哪天显示；TIME只同步当前北京时间，不是天气来源发布时间。

更新日期：2026-11-02。文档入口见 [文档导航](README.md)，工程状态见 [totalPLAN.md](totalPLAN.md)。保留旧 TIME，并新增 TIME2 亚秒校时与 TIME? 实时查询。本功能接收发送端提供的北京时间，不进行晶振频率补偿。构建及镜像身份统一见[验证记录](测试数据.md)；下文2026-10-27数据为历史记录。本次未烧录，联网校时后误差不超过100ms仍待发送端与实机共同验证。

操作前先在启动/动作清醒窗口取得 `OK POWER HOLD`，再 `CONSOLE ON`；维护完发送 `POWER AUTO`。仅进入控制台不保持清醒，详见[低功耗](low_power.md)。RTC_BKP_DR1记录已验证的授时状态。备份域初始化后显示“时间未同步”，TIME?返回`ERR TIME UNSYNC`。成功TIME/TIME2写入并验证授时标记，普通MCU复位保留日历和标记。升级前的固件没有此标记，首次升级后须授时一次。失败写入在当前运行期保留RTC故障，复位后仍需重新授时。具体状态见[修复记录](current_code_gaps.md)。

## TIME2 与 TIME?

这两条新命令仅在 `CONSOLE ON` 后接收。旧 `TIME` 保持24字节整秒格式，默认JustFloat模式下的行为也保持兼容。新命令正文为29字节，使用北京时间UTC+8，不带时区后缀。

```text
CONSOLE ON
TIME2 2026-11-02T10:30:00.750
TIME?
```

示例时间必须替换为发送时的真实时间，每行等待最终结果。TIME2 的时间戳应对应完整命令到达接收端的时刻；PC发送器需估计主机、USB和串行发送延迟，重试时重新取时。固件当前的 RX 是 **debugTask消费到行终止符的tick**，尚未在USART2中断里记录线上的CR到达时刻。因此不能把 RX 当作物理接收时间，更不能仅凭 OK 判断100ms达标。今后发送器应通过 TIME? 测量往返时延，并在负载下验证这个差异。

成功结果携带真实RTC亚秒读回，例如：

```text
OK TIME2 2026-11-02T10:30:00.753 RX 4100 SAMPLE 4104 SPAN 0
OK TIME? 2026-11-02T10:30:01.250 RX 4600 SAMPLE 4601 SPAN 1
```

`RX` 和 `SAMPLE` 是设备1000Hz单调tick，约49.7天回绕一次，以无符号差计算间隔。`SAMPLE` 对应RTC的 GetTime 开始时刻。`SPAN` 是 GetTime/GetDate 的软件读取跨度，单位ms；它只界定这次读操作，不能当作网络授时误差。查询由defaultTask读RTC，不返回一秒缓存。它不写RTC、不重置WIFI同步年龄、不授予预报许可。TIME2成功会记录同步，并为当前控制台授予一次旧FORECAST许可。

接收端补偿 RX 到defaultTask执行的排队时间。超过2000ms或跨越2099年末的输入在写RTC前拒绝，保留原RTC可信状态。平台在一次INIT内写完整日历，再使用RTC的 `SHIFTR.ADD1S/SUBFS` 调整亚秒相位，等待移位与影子同步，按实际经过时间验证。沿用异步127、同步255预分频，RTC亚秒分辨率为1/256秒，约3.906ms。旧闹钟、备份域标记与预分频保持原值。

工程保护值为读取跨度不超过4ms、平台操作不超过50ms、读回与补偿后的本地目标相差不超过20ms。它们是首版软件拒绝阈值，尚未经过实机时序验收。`OK TIME2`仅说明这组本地操作和读回通过，仍需要可信参考时间、往返测量和主机误差边界来验证100ms目标。先前的PC/USB延迟和debugTask收行积压不会自动被这组阈值覆盖。

| 结果 | 含义 |
| --- | --- |
| `ERR TIME2` | 格式、亚秒位数或日期无效，未写RTC |
| `ERR BUSY` | 旧TIME、新请求或文件/预报事务在途 |
| `ERR TIME2 TIMING` | 排队、读取或平台操作超过软件时间预算 |
| `ERR RTC` | RTC不可用、IO或相位读回失败 |

在途请求阻止退出控制台。TIME2、TIME?与旧TIME共享单请求邮箱，只有defaultTask访问RTC，debugTask负责最终应答。写入后失败会沿用RTC不可信锁存，下次成功TIME或TIME2可恢复；单独TIME?不能解除锁存。接受前的坏参数和写入前过期拒绝不会改变RTC。结果发送失败不会撤销已经成功的校时。

目标板验收应覆盖不同秒内相位、跨秒/跨日、负载与重试。发送端记录可信参考时刻和误差边界、请求发送和应答接收时刻；使用查询返回的SAMPLE定位设备采样，并把往返抖动计入误差区间。若该区间不能证明绝对误差不超过100ms，必须报告失败或无法证明，不能用屏幕翻分钟代替RTC测量。

## 连接与格式

使用 H10 的 USART2，115200、8N1、3.3V TTL。发送端 TX 接 STM32 PA3，接收端 RX 接 PA2，双方共地。板载 ESP32-C3 原连接 USART1（PA9/PA10）；本功能只接收 USART2，外部 ESP32 测试需接到 H10。

```text
TIME 2026-10-27T14:30:00\r\n
```

固定正文为 `TIME YYYY-MM-DDTHH:MM:SS`，共24个 ASCII 字节。命令区分大小写，`TIME` 后只有一个空格，日期与时间之间为大写 `T`。所有字段补零，使用北京时间 UTC+8、24小时制，不附加时区、星期或毫秒。年份2000—2099，日期必须真实有效，秒为00—59。星期由 STM32 计算。

示例中的 `\r\n` 表示实际字节 `0D 0A`，不是四个可打印字符。也接受单独 CR 或 LF。收到行结束符后才处理；普通命令31字节上限保持不变。发送端应在发送前取当前时间，一次连续发送完整行；重试时重新获取时间，避免重新发送旧时间字符串。

## 模式与结果

默认 JustFloat 模式也接受 TIME，但成功、无效内容和失败都不输出文本。需要确认结果时，先发送 `CONSOLE ON` 并等待 `OK CONSOLE ON`，再发送 TIME。

```text
CONSOLE ON\r\n
TIME 2026-10-27T14:30:00\r\n
```

| 控制台应答 | 含义 |
| --- | --- |
| `OK TIME\r\n` | 完整日历写入、RTC 同步和读回验证均成功，已发布时钟模型并记录同步成功 |
| `ERR TIME\r\n` | TIME 参数格式或日历无效，未提交硬件写入 |
| `ERR RTC\r\n` | 时钟任务不可用，或 RTC 写入、同步、读回验证失败 |
| `ERR BUSY\r\n` | 上一次校时尚未完成并取走结果，或校时期间请求退出控制台 |
| `ERR RX\r\n` | 接收损坏或超长，整行已丢弃 |

`TIME?` 使用上节的新查询流程。其他未知命令在控制台沿用 `ERR COMMAND`，默认 JustFloat 模式保持静默。每次只允许一个校时请求在途，控制台收到结果后再发下一条 TIME 或 `CONSOLE OFF`。旧TIME应答由提交时的模式决定：默认模式提交后即使进入控制台，也不补发该请求的应答。TIME 与 FORMAT 的在途状态独立，可同时进行；WEATHER、PAGE 和 ERRORS 保持可用。串口模式、应答错误和收行长度规则见 [控制台协议](debug_console.md)；天气来源时间仍仅用于显示，见 [天气协议](weather_protocol.md)。

合法时间可向前或向后调整任意幅度。`OK TIME` 表示 RTC 已完成操作，不表示墨水屏已经刷新。串口、主机发送和任务调度延迟不作毫秒补偿；秒级效果需在板上测量。

## 发送端校时建议

针对刚校时就相差接近一秒的情况，先检查发送端的时间源、取时和发送顺序。当前 TIME 只携带整秒；如果参考时间是 `12:00:00.950`，格式化成 `12:00:00` 就丢失了950 ms信息。接收端无法从这条消息还原秒内相位，因此仍可能产生接近一秒的偏差。实际偏差还受传输、调度和 RTC 应用相位影响。

### 当前协议下的发送步骤

1. 先确认时间源可靠。电脑应先完成系统时间同步；ESP32应先完成自身的NTP/SNTP同步，再读取当前时间，不能直接重发之前取得的时间值。统一转换为北京时间 UTC+8；已经是北京时间的值不要再加8小时。板载ESP32自动联网和USART1校时尚未接入，本节只指导发送端实现。
2. 先打开串口并完成前置交互。需要应答时，发送 `CONSOLE ON` 并等待 `OK CONSOLE ON`；预报或文件会话须先按对应协议完成或退出，再进行校时。完成这些等待之后才生成 TIME，避免时间字符串在等待中变旧。
3. 自动发送时，尽量在参考时钟刚进入新的一秒时，立即重新读取当前北京时间并生成完整命令。检测边界需要秒以下的时间信息；不要只依靠固定等待一秒或手工点击。错过边界后应等待下一次边界并重新取时，不发送之前预备的旧值，也不提前发送未来一秒的值。
4. 一次连续发送整行，例如 `TIME 2026-10-30T14:30:00\r\n`，使用实际CRLF，不逐字符添加延时。示例日期只表示格式，使用时替换为发送时的真实北京时间。
5. 控制台等待 `OK TIME` 后再发送后续命令。超时或失败重试时重新获取当前时间；收到 `ERR BUSY` 先处理在途请求或会话。多天预报继续遵循先TIME成功、再BEGIN的顺序，见[多天预报协议](forecast_protocol.md)。

整秒边界发送能减少秒内信息截断，但电脑调度、USB转串口缓冲和接收处理仍有延迟或抖动。发送API返回或主机输出缓冲排空，也不能直接证明STM32已经完成RTC写入。当前做法不保证100 ms或其他亚秒精度。

当前解析严格要求24字节正文，**不支持毫秒或时区后缀**。例如 `TIME 2026-10-30T14:30:00.950`、附加 `Z` 或 `+08:00` 都是无效TIME参数；控制台返回 `ERR TIME`，默认模式保持静默。发送端不能单独改成小数格式而期待当前固件生效。

### 提速的收益与精度扩展

115200、8N1下，26字节的完整CRLF行线传输时间为 `26 × 10 / 115200 ≈ 2.26 ms`，不含主机、USB和任务调度延迟；解析在收到CR时就可开始。即使将双方改成460800，完整行也只是缩短至约0.56 ms，节省约1.7 ms，无法消除近一秒的信息损失。当前固件仍配置115200，单独提高串口助手的波特率会造成通信参数不匹配。

TIME2已加入亚秒信息、owner排队及平台耗时补偿、RTC亚秒相位调整与读回。接收中断的物理到达时间戳仍未加入；PC发送器、主机/USB延迟与往返测时仍需配套实现和验收。仅补偿设备内的排队时间，无法自行得知上游延迟。旧TIME继续使用整秒方式。

### 分开测量RTC与显示

校时请求会立即通知时钟任务，不必固定等待下一次一秒轮询。普通日历缓存仍每1000 ms更新一次，显示任务每200 ms检查一次；分钟翻转还需经过绘制、传输和屏幕BUSY。因此屏幕晚约一秒翻分钟，不能单凭画面认定RTC本身慢了一秒。

验证时分别记录可靠参考时间、发送时刻、RTC应用及亚秒读回、屏幕可见变化。覆盖不同秒内相位、重复校时和通信负载，统计实际偏差；`OK TIME`、`OK TIME2`、`WIFI 0h ago`及现有主机桩测试均不能代替这项精度测量。TIME?提供defaultTask实时读取的RTC日历与亚秒值，避免把缓存模型当作实时RTC。

若刚校时准确、运行后逐渐偏离，应另测长期晶振频偏；每天累积一秒约为11.6 ppm。后续可评估RTC平滑频率校准及周期校时，周期应根据实测漂移和允许误差选择，不能用一次通信抖动估计晶振频偏。当前固件没有自动频率补偿。

## WIFI 同步记录

TIME 只有在 RTC 写入、同步和读回验证全部成功后，才在发布时钟模型的同一临界区记录本次成功；仅接受请求、参数错误、忙拒绝或 RTC 失败均不计入。记录与应答发送独立，默认静默模式同样生效，`OK TIME` 发送失败也不撤销成功记录。完整有效 WEATHER 的成功提交也会重置同一记录。

时钟页沿用 `WIFI` 标签显示距上次成功同步的整小时：启动后无记录为 `N/A`；成功后为 `0h ago`，满一小时为 `1h ago`；达到100小时后锁存为 `99h+`，直到下一次成功。记录仅存 RAM，失败保留此前计时，重启清空。每秒时钟服务使用单调 tick 维护并支持回绕，RTC 前后跳变不会拉长或缩短经过时长；成功 TIME 作为新事件归零。PAGE、FORMAT、文件维护和普通串口流量不计入，不新增网络或信号判断。

独立验收时串口助手设为115200、8N1、UTF-8和自动CRLF，发送前把示例替换为当前真实北京时间；逐行发送，并依次等待 `OK CONSOLE ON`、`OK TIME`、`OK PAGE CLOCK`：

```text
CONSOLE ON
TIME 2026-10-28T14:30:00
PAGE CLOCK
```

待时钟画面刷新完成，检查 `WIFI` 为 `0h ago`。同分钟校时若导致 `N/A→0h ago` 或非零小时归零，仍会请求刷新；已显示零小时的同分钟重复成功不追加刷新。天气和故障页隐藏字段时不因该记录变化追加刷新，返回时钟页时使用最新值。天气路径验收及完整状态表见[天气协议](weather_protocol.md#wifi-同步记录与验收示例)。

## 任务与故障处理

debugTask 负责收行、校验和应答，defaultTask 独占运行期 RTC 读写。校时请求通过静态单请求邮箱传递，并通知时钟任务立即处理；邮箱保留到 debugTask 消费完成结果后才释放。时钟服务保留独立的一秒轮询截止时间，校时不重置该周期；操作耗时跨过截止时间时跳过错过的轮次，避免连续补跑。

平台适配器预先编码日期时间，在一次 INIT 中写入 TR/DR，退出并同步后按 GetTime、GetDate 顺序读回。允许读回时正常前进一秒，包括跨日、跨月和普通年界；2099年末不将 Year=00 的世纪歧义视为2000年校时成功。适配器使用当前 STM32L4 HAL 的 RTC 内部辅助函数，升级 HAL 时应复核该封装。

HAL 等待期间保持中断开启。所有退出路径恢复 RTC 写保护并释放句柄锁。运行中发生写入或验证失败后，服务锁存 RTC 不可信状态，普通轮询读到合法日历也不会自动恢复；下一次完整校时成功才恢复 READY。该锁存保存在 RAM，不承诺校时过程中断电或复位的事务恢复。

校时保留备份域初始化标记、预分频及闹钟配置，普通复位保时继续依赖备份域供电。跨过的闹钟不补发。成功后立即更新模型、同步记录与故障时间锚点，历史故障记录不改写。日期、分钟或可见 WIFI 状态/整小时值变化由显示任务更新画面；同一分钟只改秒且 WIFI 显示不变时不增加刷新。天气三小时过期、页面轮换、加速度遥测时间戳及序号仍使用原有单调时间或计数规则，不因 TIME 前后跳变而重置。
