# 四键浏览与接口

更新日期：2026-11-04。返回[文档导航](README.md)。进度见[统一进度](totalPLAN.md)，构建身份及验证范围见[验证记录](测试数据.md)。本功能尚未烧录或完成实板验收。

## 操作

| 历史键号 | 历史引脚 | 按下一次 |
| --- | --- | --- |
| SW3 | PC10 | 上一页 |
| SW4 | PA15 | 下一页 |
| SW5 | PC12 | 回时钟 |
| SW6 | PC11 | 暂停／恢复轮播 |

映射依据历史网表，历史设计为外部下拉、按下高有效。当前四路GPIO已配置上升沿EXTI。实际板号、键号、电平和左右顺序须在上板前核实；差异集中修改 `platform/stm32_buttons`，不改变业务或消抖模块。SW1、SW2不纳入四键业务。

- 按下稳定30毫秒触发一次；保持按住不连发，释放稳定30毫秒后才能再次触发。活动期间每10毫秒采样，无输入时任务阻塞。多键独立消抖，同时产生的事件按上页、下页、时钟、轮播的固定顺序处理，不定义组合键。
- 有WDATA时，前后循环浏览时钟、实况、三日预报、六格数据；没有时只浏览时钟和旧天气。沿用现有available判断，WDATA的STALE不改变页面集合。
- 手动翻页和回时钟均重新计算该页停留时间；时钟180秒，WDATA天气页60秒，无WDATA天气180秒。暂停期间操作保持暂停；恢复轮播从当前页重新计时。
- 暂停时所有正式页面右上角显示小型双竖线标记。暂停只停止定时切页，分钟更新、数据更新和重要预警继续工作。状态只在RAM中，重启回时钟并恢复自动轮播。
- 有效旧WEATHER和新FORECAST提交继续按现有规则切到天气页，暂停状态保留；普通WDATA更新保持页面。此处不实施差异清单中的R5需求。
- 新重要预警仍抢屏，原有60秒期限和失效退出规则不变，结束后回原页并保留暂停状态。上／下页以抢屏前页面为起点翻页并确认旧预警，时钟键直接退出；轮播键只切换轮播状态，不确认预警或重置其期限。串口选择的详情页不在普通集合中，实体翻页以时钟为起点。
- 系统休眠时首次有效按键同时唤醒并执行。刷新期间每次有效操作都更新目标，当前刷新安全完成后直接处理最新目标，不为中间页面排队刷新。

## 分层

| 模块 | 所有权与依赖 |
| --- | --- |
| Core | USER区域只保留输入任务启动和EXTI15_10转发，不放按键状态机 |
| platform/stm32_buttons | 独占四键引脚映射、电平归一化、EXTI待决记录；依赖HAL，不识别页面或轮播 |
| platform/stm32_gpio_exti | 唯一HAL_GPIO_EXTI_Callback入口，分发给按键与ADXL345适配器；各适配器只接受自己的引脚 |
| middleware/button_filter | 调用方持有状态，纯C消抖；没有HAL、RTOS、全局业务状态或内部时钟读取 |
| app/buttons | 静态输入任务和消抖状态、四键到四种操作的映射、INPUT禁睡位；调用platform、middleware和display接口 |
| app/display | 独占页面、轮播和预警返回状态；短临界区更新RAM；不读取GPIO、不等待屏幕 |
| app/epd_bringup | 显示任务内消费一致快照，合成暂停标记并执行刷新；其他任务和ISR不得调用绘制或刷新 |

GPIO按键没有独立器件协议，不增加device模块或通用事件总线。

## 接口契约

`stm32_buttons_init(notify_from_isr)` 在GPIO初始化后、RTOS启动前调用。先注册回调，再以优先级5启用EXTI15_10。`read_pressed_mask()` 返回归一化的BUTTON_1..4位图。`take_pending()` 在任务上下文原子消费软件记录，不清除尚未分发的硬件边沿；记录用于唤醒和阻止睡眠，不直接作为有效按下事件。

`stm32_buttons_sleep_ready()` 只读检查初始化状态、软件记录、EXTI待决位和实体电平，允许在屏蔽中断的STOP2最终检查中调用。它不清事件、不调用RTOS接口、不等待。Core向 `stm32_buttons_irq()` 转发中断；共享HAL回调分别调用两个适配器，保持动作中断原有遮蔽和通知语义。

`button_filter_init(ctx)` 清空调用方状态。`button_filter_update(ctx, raw_mask, now_ms)` 返回 `pressed_mask` 和 `needs_sampling`，每键独立计算稳定时间，接受uint32毫秒时间回绕，屏蔽四键以外的位。调用方保证活动期间采样，空指针不产生事件。

`buttons_start()` 仅在RTOS初始化时调用，使用1024字节静态栈和静态任务控制块。重复成功调用不重复创建任务。启动失败返回false，启动入口记录任务故障并保留禁睡状态；实际栈裕量待板测。ISR通知使用FromISR接口，任务独占消抖上下文。

`display_handle_action(action)` 仅接受PREVIOUS、NEXT、HOME和TOGGLE_CYCLE；非法值返回false且不改变状态。调用仅限任务上下文，成功后只表示目标已更新，不表示屏幕已经完成刷新。连续调用依次作用于最新RAM目标，不依赖上次刷新是否完成。旧串口接口保持兼容，共用内部手动选页逻辑；不存在按键生成串口字符串的路径。

`display_snapshot_t.cycle_paused` 与页面一起在原临界区中捕获，没有对外可写状态。显示任务只在物理刷新成功后提交对应标记状态；暂停切换触发全刷，后续分钟局刷保留标记。模式7独立诊断画面保持原义。

## 睡眠边界

新增 `POWER_BLOCK_INPUT`，位7，唯一所有者为输入任务。任务采样、消抖、处理业务及等待稳定释放期间持有；确认所有键释放且无待决事件后释放。初始化阶段该位默认置位。

中断只记录并发送ISR安全通知。禁睡释放与任务阻塞之间发生的新边沿由软件记录和任务通知保留；STOP2在初次关中断检查和最终WFI前均检查输入适配器。最终检查之后的有效边沿仍由硬件EXTI待决状态唤醒。按键不调用 `power_motion_event()`，不增加动作计数或动作清醒窗口；单独由按键触发时统计归为OTHER唤醒。

按住期间保持清醒；若实物输入卡在高电平，会持续禁止STOP2，待修复输入后自动恢复。暂停轮播本身不禁止睡眠，也不延长串口维护窗口。

CubeMX重新生成时，若生成EXTI15_10处理函数，应将USER区转发移入生成函数，删除重复USER定义；保留共享回调、启动调用、NVIC优先级和Keil新增源文件。当前不修改生成区域外的内容。

## 验证和板测

主机入口为 `tests/run_buttons_host.ps1`，覆盖纯消抖和真实输入任务／GPIO适配器的模拟；页面与预警测试在 `run_weather_pages_integration_host.ps1`；真实帧缓冲和控制器模型测试在 `run_clock_partial_host.ps1`，新增暂停时钟／旧天气／WDATA及BUSY连续按键场景。

实板验收须记录板号、供电、构建配置及镜像SHA256，再执行：

1. 核实四键对应引脚及按下电平，确认SW1/SW2未被接入业务。逐键短按、长按、松开再按，验证无连发和误触。
2. 分别在两页和四页数据条件下验证前后循环、回时钟、停留计时及暂停／恢复；重启确认默认状态。
3. 暂停后注入旧WEATHER、FORECAST和WDATA，检查各自切页规则及暂停标记；新增重要预警检查抢屏、退出和返回。
4. 屏幕BUSY期间连续按两次下一页，检查最终前进两页且不补刷中间目标。检查标记不遮挡正文、日期或数据。
5. 在静置AUTO进入STOP2后逐键执行首次操作，重复至少100次，覆盖临近入睡的按下；释放后结合电流和睡眠统计确认重新睡眠，保留ADXL345动作唤醒。
6. 记录输入／显示任务栈高水位和长按功耗。主机模拟、构建通过和软件睡眠计数均不能代替真实中断时序、显示及功耗验收。
