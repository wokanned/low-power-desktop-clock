# 历史：天气发送端、校时与大字天气界面

整理日期：2026-11-02。这是上一轮讨论的需求和设计交接，不是功能完成报告。新对话应先读本文件，再读仓库规则和实际源码。

## 1. 用户希望继续做什么

在 Windows 本地写 Python 程序，获取可靠时间及天气，通过串口模拟将来 ESP32 的发送功能；配套扩展 STM32 固件的数据模型、协议与显示，落地已迭代的天气页面。最终 ESP32 可复用同一业务协议，但首阶段用 PC 联调，不要求同时开发 ESP32 联网固件。

本轮主要完成了研究、现有校时文档补充和交互原型。**Python 自动天气发送器、新校时精度方案、新数值页、新预警系统均未实现。** 用户准备在新对话开始写代码；不要重新从零设计界面，也不要把原型当作已烧录功能。

用户沟通偏好：直接推进有依据的工作，少问重复问题，不要每一步都申请确认。发现真正影响实现的未知项时集中说明，并给建议。用户曾调用 grill-me，希望认真审视方案，但不喜欢与目标无关的多选题或不断追问。

## 3. 已确认的界面要求

### 总体要求

1. **所有设备界面不显示“和风天气”四个字。** 不要重新加回。
2. 尽量使用短英文标签和大数字，减少中文和小字。信息密度、字号及格子间距参考现有时钟界面，不追求手机天气 App 式堆砌。
3. 温度数值和 `°C` 紧邻，不要把符号放到很远的位置。单位随数字宽度动态定位，并覆盖负数和不同位数。
4. 高低温直接显示 **`27~18`（最高~最低）**，不写“高27 / 低18”。
5. 普通天气页面的预警提示**专门放在底部**，不要移回顶部。
6. 先保留现有时钟主布局。原型里的“时钟参考”只是当前 C 测试帧，用于对照字号和密度，不是实时板照。
7. 原型按钮、标签页与切换控件只是预览工具，不能据此宣称固件已经有实体按键交互。

### 页面内容：以最新原型为准

| 页面 | 内容和排版 |
| --- | --- |
| 实况 | 城市 / UPD 时间；天气图标 + 短英文天气名；大号 `23.5°C`；`27~18`；`RH 72%`；`NE 3~4 Bft`；底部预警条 |
| 三日预报 | 三列，TODAY / 后两天星期；英文天气名；最高~最低温；`RAIN 20%` 等降水概率；底部预警条 |
| 数值 | **已把“数值1”和“数值2”合为一页，三列两行六格**；上排 FEELS / UV / AQI-CN，下排 RAIN 1h / PRESS / VIS；底部预警条 |
| 预警概览 | 很大的英文类型 RAIN / STORM / WIND 等，ORANGE / BLUE 等级词，有效期；减少中文和小字；可切多条预警 |
| 预警正文 | 官方中文正文与防御指南分别分页阅读，约26 px、每屏两行，按语义断行；保留正文，不用一屏挤下全部文字 |
| 预警来源 | 发布机构、发布时间和有效截止时间单独阅读页，避免挤占概览 |

数值页示例：`FEELS 25.1°C`、`UV 6.0`、`AQI-CN 42`、`RAIN 1h 0.0mm`、`PRESS 1012hPa`、`VIS 18km`。这些数值是设计样例，不是实测数据。

用户说“我只要数据，重新排”：这里的“天气指数”最终收敛为体感、UV、AQI、降水等物理数据，不要擅自改成穿衣、洗车、运动建议四宫格。

### 预警行为和状态

- 用户明确选择：**重要预警自动切详情，其余显示提示条；首版不响铃。**
- “重要”的具体阈值尚未最终确认。曾建议按官方严重程度、紧急程度与橙/红等级判断；不能把建议写成用户已确认的硬规则。
- 需要区分：有重要预警、一般预警、查询成功且无预警、查询失败/离线、预警解除。
- 底部条显示类型/等级、数量、最近检查时间，例如 `RAIN / ORANGE  2` 与 `CHK 10:35`。离线显示 `ALERT: OFFLINE` 和上次成功时间；失败不能当作无预警。
- 实现时按预警 ID 和更新关系处理新增、升级、更新、取消、到期，避免相同内容每次轮询都抢屏。具体停留时长、返回页面、多条排序、实体按键映射仍属待定实现细节。
- 原型正文是少量手工语义分页的样例，**没有证明任意真实长文本的自动分页已实现**。固件必须设计通用分页、UTF-8、安全长度、缺字段和长内容处理。
- 任意中文预警正文超出现有固定中文字形子集，需要实际设计字库或外部字形方案；不能仅把原型PNG整屏复制就宣称动态文字已支持。

### 字体和锯齿

- 用户明确不满意英文斜笔画的强烈锯齿，后续改用 **Terminus 原生点阵英文字体**，保持纯黑白与整数像素布局。
- 小英文使用对应14/16/18 px原生点阵；较大英文用20/24/32 px粗体；超大英文预警标题用32 px粗体整数2倍最近邻放大。
- 大数字原型使用 Bahnschrift；中文原型使用 Microsoft YaHei。Windows 字体用于设计不等于已解决固件资源分发许可，固件落地时核对字体许可和可分发字形资源，不擅自牺牲已认可视觉风格。
- 点阵字改善的是笔画一致性，不会消除黑白屏的物理台阶。不要用网页灰度/小数缩放制造假效果。
- 原型图像是296×128的1-bit PNG；预览只能1×或2×等整数缩放。名义12 px标签实际选择Terminus14的裁边墨迹，不要机械理解为所有字体都有完全相同的12 px外框。
- 最新数值页：标签名义12、数值24、单位12，参考现有时钟信息格；主实况温度名义54。具体坐标以渲染脚本为准。
