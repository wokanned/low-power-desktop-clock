# 低功耗物联网桌面时钟 技术方案文档

## 项目概述
设计一款基于 STM32L471RET6 的低功耗桌面时钟。设备使用 2.13 寸电子纸显示时间和状态，支持温度、气压和环境光采样，带本地闹钟提醒，并通过 ESP32-C3-WROOM-02-N4 以低占空比方式联网完成校时和天气刷新。

这份文档按个人项目的小量制作收敛。器件优先级按这四项排，先看手工焊接友好度，再看嘉立创商城是否有资料或搜索结果，再看首板容易做通，低功耗和功能完整放到后面比较。

V1 先做这些内容。
1. FreeRTOS + Tickless Idle 的低功耗框架。
2. 电子纸显示、RTC 保时、NTP 校时。
3. 简化天气刷新。
4. 温度、气压、环境光采样。
5. 本地闹钟提醒。
6. W25Q128JV 的字库、图标、缓存和日志。
7. 电量计、低电量限制和分域断电。

V2 再看 LVGL、OTA 和更复杂的远程内容。

## 当前结论
1. 产品定位收敛为低占空比联网的环境时钟。
2. 主控固定为 STM32L471RET6。
3. 联网模块固定为 ESP32-C3-WROOM-02-N4，只在定时任务时上电。
4. 外部存储固定为 W25Q128JV。
5. 电池固定为 1000mAh 三线锂电，第三根线预留给温度检测。
6. 主电源按单节锂电、BQ24074、TPS631000 和 3 路 SY6288D20AAC 推进。
7. 首版目标先做到周到月级稳定续航。年级续航放到后续优化。
8. 首板按 STM32L471 核心板加大部分器件验证板推进。
9. 气压传感器固定为 MPL3115A2。
10. 加速度计改为 ADXL345，优先解决首版手工焊接难度。
11. 首版所有器件都按可直接焊到主板、且至少能用加热台或热风枪稳定焊接来筛选。

---

## 首版器件封装筛选原则

1. 优先使用 LQFP、SOIC、SOP、SOT-23、邮票孔模组，以及尺寸更大的 LGA、QFN、TDFN 和 SOT-5X3。
2. 同一器件族若存在多种封装，只保留能直接焊主板、且适合加热台或热风枪的版本。

这版器件有四个固定项。STM32L471RET6、ESP32-C3-WROOM-02-N4、W25Q128JV 和 1000mAh 三线电池都直接按既定方案推进。

首版封装路线也一起锁定。W25Q128JV 只买 SOIC-8 或 SOP-8，MAX17043 只买 2mm x 3mm TDFN-8，BQ24074 固定 VQFN-16 (RGT)，TPS631000 固定 SOT-5X3-8 (DRL)。这版不再接受只写通用型号、不写封装约束的下单方式。

本地唤醒用的 IMU 改为 ADXL345。它的封装是 3mm x 5mm LGA，比 LIS2DW12 更大，保留 tap 和 activity 这类唤醒能力，首版在手工焊接和调试上更现实。

气压传感器改为 MPL3115A2。它是 5mm x 3mm x 1.1mm LGA，1.25mm 引脚间距，封装比 LPS22HH 大一档，手焊容错更高。它的采样电流比 LPS22HH 略高，但本方案本来就是按需上电采样，这个取舍对首版更合理。

V1 的 RAM 压力主要来自这几块，显示缓冲、UART 缓冲、天气解析、FreeRTOS 任务栈、队列和 RTOS 堆。STM32L471RET6 的 128KB SRAM 对当前方案已经够宽裕，不需要为了首版再压主控。

任务拆分先控制在最小集合，保留 PowerMgr、UiRefresh、NetSync、SensorHub 和 LogStore 这 5 类职责。闹钟提醒采用 RTC 事件触发的状态机，不单独拉常驻任务。

## 电源树

### 1. 主电源结构
1. USB Type-C 5V 先进入 BQ24074 这类带 Power Path 的单节锂电充电芯片。
2. 电池 BAT 节点同时接电量计和 MCU 的电池分压采样通道。
3. BAT 再经过 TPS631000 统一转换为系统 3.3V 主电源。

### 2. 3.3V 分域
1. 3V3_SYS 供主控、RTC 相关外围、外部 Flash 和 IMU。
2. 3V3_WIFI 只供 ESP32-C3-WROOM-02-N4，由一颗 SY6288D20AAC 独立关断。
3. 3V3_HMI 供 FT6336U 和前置光控制，由一颗 SY6288D20AAC 供电。前置光后面仍保留独立驱动。
4. 3V3_SENS_SW 供 TMP1075DR、MPL3115A2 和 VEML7700，由一颗 SY6288D20AAC 按需上电。
5. 3V3_BUZZ 直接挂主 3.3V，由定时器 PWM 单端直驱无源压电蜂鸣器。

### 3. SY6288D20AAC 的判断
1. 这颗集成负载开关对 HMI 域和传感器域已经可以视为明确可用。
2. 对 ESP32-C3 域也基本够用，首板重点验证 WiFi 域的输出电容、软启动和上电建立时间。
3. 相比分立 PMOS，它的优势更实际。高边开关特性更明确，带限流和保护，调试成本更低。
4. FT6336U 当前和 HMI 共用电源域。

### 4. LDO 使用原则
1. 不把 LDO 当整机主 3.3V 的必需器件。
2. 只有在 VDDA 或新增模拟支路对噪声更敏感时，再加局部 LDO 位。
3. 本版主线采用 TPS631000 直接生成 3.3V。

## 低功耗工作流程

### 1. 深度休眠
1. MCU 进入 Stop 2，RTC 保持计时。
2. 电子纸保持最后画面。
3. ESP32-C3 所在电源域默认完全断电。
4. IMU 保持低功耗运动检测，作为本地唤醒源。
5. 若 FT6336U 常开做触控唤醒，待机会额外增加约 55uA。

### 2. 唤醒方式
1. 轻拍桌面，由 IMU 中断唤醒。
2. RTC 定时唤醒，用于联网、校时和闹钟提醒。
3. 触控唤醒只在 3V3_HMI 常开时成立。

### 3. 唤醒后动作
1. 恢复系统时钟和必要外设。
2. 按事件拉起对应电源域。
3. 采样事件时，打开 3V3_SENS_SW 读取温度、气压和环境光。
4. 联网事件时，打开 3V3_WIFI，完成 NTP 校时和天气刷新后再断电。
5. 闹钟事件时，由提醒状态机驱动蜂鸣器，支持触控或按键消音。
6. 日志统一由 LogStore 写入 W25Q128JV。

### 4. 再次休眠
1. 关闭 3V3_WIFI、3V3_SENS_SW 和蜂鸣器驱动。
2. 若不需要触控唤醒，同时关闭 3V3_HMI。
3. 保留 IMU 和 RTC。
4. 重新进入 Stop 2。

## 续航估算

1. 整机待机电流主要取决于 IMU、FT6336U 是否常开、板级漏电和电源分域策略。
2. 若 FT6336U 常开做触控唤醒，待机会被抬到数十微安量级，年级续航会明显变难。
3. 前置光开启时电流不高于 45mA，只能算短时功能。
4. ESP32-C3 的平均功耗取决于上电、入网、传输和断电总时长，不能只看睡眠电流。
5. TPS631000 的静态电流和轻载效率也要算进模型。
6. 估算公式保持为平均电流 = 待机电流 + Σ 事件电流 × 事件时长 / 事件周期。
7. 首版先追求周到月级稳定续航。后面再根据实测决定是否继续冲更长续航。

## 开发计划

1. 第一阶段绘制 STM32L471 核心板加大部分器件验证板，把主电源、3 路 SY6288、屏模接口、ESP32-C3-WROOM-02-N4、W25Q128JV、MAX17043 和主要传感器一次收上板。
2. 第二阶段验证电子纸刷新、待机电流、分域上电时序和主 3.3V 稳定性。
3. 第三阶段完成 ESP32-C3 上电、自定义联网协议、NTP 校时和天气刷新。
4. 第四阶段接入温度、气压、环境光页面和本地闹钟提醒。
5. 第五阶段建立 W25Q128JV 的循环日志和天气缓存。
6. 第六阶段再做 Bootloader、升级包缓存、低电量限制和失败回退预研。

## PCB 前检查清单

1. 首版 PCB 按 EVT 验证板来做，别太早删掉调试口和测量点。
2. 第一版把 TPS631000、3 路 SY6288D20AAC、W25Q128JV、MAX17043、ADXL345、MPL3115A2、TMP1075DR、VEML7700、ESP32-C3-WROOM-02-N4 接口和屏模 FPC 一起收上板。
3. 先把 USB 输入、充电、电池、电量计、主 3.3V、ESP 域、HMI 域和传感器域拆清楚。
4. 预留 SWD、串口日志、ESP32-C3 USB 下载调试口、主电源测流点和前置光测流点。
5. TPS631000 的输入输出电容、电感和高频走线按开关电源标准处理。
6. 3 路 SY6288D20AAC 的 EN、去耦、电源默认状态和测试点一次放全。
7. 电量计预留 ALERT 引脚和电池分压采样通道。
8. RTC 相关的 LSE 32.768kHz 晶振、备份域和唤醒引脚在原理图阶段就定下。
9. 屏模接口按 GDEY0213B74-FT11 实际图纸处理，同时确认 FPC 方向、连接器高度和结构空间。
10. IMU 中断、RTC 唤醒和触控中断的引脚规划一次想清楚。
11. I2C 地址、上拉阻值、中断脚预算和 SPI 片选在原理图阶段核对完，避免后面飞线。
12. 蜂鸣器按无源压电蜂鸣器预留焊盘和定时器 PWM 驱动。
13. 前置光和 ESP32-C3 都有峰值电流，电源部分按峰值选型。
14. ESP32-C3 继续由 SY6288 分域控制，USB 下载调试通过上电旁路处理。
15. 机械结构要提前确认，尤其是屏模厚度、FPC 弯折方向和电池仓空间。
16. ADXL345、MPL3115A2、MAX17043、BQ24074 和 TPS631000 这类 B 级封装统一按热台预热加热风回流规划，不要按纯烙铁拖焊预期来排期。
17. 下单前逐项复核封装版本，至少锁死 W25Q128JV 的 SOIC-8 或 SOP-8、MAX17043 的 TDFN-8、BQ24074 的 RGT、TPS631000 的 DRL。

## 当前原理图跳线帽与电源选择说明

1. H1 用于 STM32L4 的 BOOT0 选择。H1.1 通过 R1 下拉，H1.2 为 BOOT0，H1.3 为 3.3V。正常运行保持 BOOT0 为低，进入系统下载模式时再切到高。
2. H3 用于 BQ24074 的 TS 与电池 NTC 选择。H3.2 为 TS，H3.3 为 NTC，三线电池使用时保持 TS 接到 NTC。
3. H4 用于 3.3V-DEBUG 参考电压选择。H4.2 为 3.3V-DEBUG，H4.3 为系统 3.3V。调试 STM32 时保持参考电压连通。
4. H5 用于 ESP32-C3 启动相关测试。H5.2 接 ESP32-C3 的 GPIO9，H5.1 为 GND。默认保持断开，仅在启动测试或下载相关调试时短接。
5. H6 用于主 3.3V 接通和测流。H6.2 为 TPS631000 输出，H6.1 为系统 3.3V。正常运行时保持接通，需要单独测主电流时再断开。
6. H7 用于 ESP32-C3 供电路径选择。H7.2 接 SY6288 的 WiFi 域输出，H7.1 为 ESPPWR。正常运行时由 WiFi 域供电，USB 单独下载调试时断开 H7，改由 U34 的 5VESP 路径供电。两条供电路径不能同时并联。
7. H10 为串口调试接口，不是业务通信口。H10.2 为 TX2，H10.3 为 RX2，H10.4 为 3.3V，H10.1 为 GND。

## 当前主要风险

1. 若 FT6336U 常开做触控唤醒，HMI 域待机电流会上升很多。
2. 前置光会拉高峰值电流和平均功耗，需要单独核算。
3. FreeRTOS 的任务栈、队列和堆配置若失控，会直接吃掉 SRAM 余量。
4. STM32L471RET6 的供货可能波动，下单前要提前锁料。
5. 电子纸更适合状态型页面，高频动画会明显拉高刷新成本。
6. ESP32-C3 只承担低占空比联网任务，高频长连接会明显拉高功耗和复杂度。
7. BQ24074 已锁定为 VQFN-16 (RGT) 版本，中心焊盘和回流质量会直接影响首板节奏。
8. 日志系统若写得太碎，会缩短 SPI Flash 寿命，需要按页追加和循环回收。
9. TPS631000 已锁定为 SOT-5X3-8 (DRL) 版本，布局和焊接窗口若处理不好，ESP 上电和前置光脉冲可能把主 3.3V 拉低。
10. OTA 以后若缺少低电量禁入、校验和回退，维护风险会很大。
11. SY6288D20AAC 的主要验证点已经收敛到 WiFi 域上电波形。
12. ADXL345、MPL3115A2、MAX17043、BQ24074 和 TPS631000 都属于首版可接受但不属于 A 级的 B 级封装，首版要给热台、热风返修和焊接工装留时间。

## 方案优势总结

1. 主线已经收敛，主控、存储、电池和电源架构都定下了。
2. 分域断电方案清楚，低功耗方向可落地。
3. FreeRTOS、日志、电量计和后续 OTA 的接口都提前留好了。
4. 当前器件大多能直接按嘉立创采购推进，资料也比较完整。
5. 首版路线明确，可以直接进入原理图和 PCB 阶段。
