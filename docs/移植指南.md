# 移植指南

## 1. 适用范围

本指南对应当前仓库里的 GDEY0213B74-FT11 墨水屏驱动实现。

当前代码已经按三层拆开：

- `device/epd_gdey0213b74.*`：屏控制器命令、时序、RAM 布局、像素映射。
- `platform/stm32_gdey0213b74.*`：STM32 HAL、GPIO、SPI、delay、tick 绑定。
- `app/epd_hello_world.*`：Hello World 场景、tick 文本、启动编排。

如果你只是换 MCU 或换板子，但屏幕型号还是 GDEY0213B74-FT11，优先保留 `device/` 和 `app/`，只改 `platform/`。

如果你换的是别的屏控制器，通常要重写 `device/`，`platform/` 和 `app/` 只做小改或不改。

## 2. 当前实现依赖的硬件事实

移植前先确认这些事实没有变：

- 屏幕有效显示区域是 122 x 250。
- 控制器 RAM 按 128 x 250 处理，所以每行按 16 字节算。
- BUSY 高电平表示忙，低电平表示空闲。
- 当前代码使用 4 线 SPI，8 位，MSB first。
- 当前逻辑坐标采用横屏视角，内部再旋转 270 度映射到控制器 RAM。
- 当前完整刷新使用 `0x22 = 0xF7`，不是快速刷新参数。
- 当前初始化的步骤 4 会执行 `0x22 = 0xB1` → `0x20` 从 OTP 加载波形 LUT，与手册 14.1 节一致。

如果这些事实里有任何一条变化，都不要直接复用当前 `device/` 文件。

## 3. 当前关键命令序列

当前驱动对齐的是这条主线：

1. 上电稳定等待 10ms。
2. 硬件复位，低 10ms，高 10ms。
3. 等待 BUSY 空闲。
4. 发送 `0x12` 软件复位，再等 BUSY。
5. 发送 `0x01`、`0x11`、`0x44`、`0x45`、`0x3C`、`0x21`、`0x18`。
6. 发送 `0x22 = 0xB1`，再发送 `0x20`，等待 BUSY，从 OTP 加载 LUT。
7. 设置 `0x4E`、`0x4F` RAM 游标。
8. 发送 `0x24` 写 4000 字节黑白图像。
9. 发送 `0x0C` 设置 booster 软启动参数（POR 值）。
10. 发送 `0x22 = 0xF7`，再发送 `0x20`，等待 BUSY，完成完整刷新。
11. 发送 `0x10 = 0x01` 进入深睡眠。

移植时若抓逻辑分析仪，建议优先核对这 11 步。

## 4. 同型号屏移植到新 STM32 的步骤

### 4.1 先重新生成基础工程

用 CubeMX 建新工程时，先把这些资源配好：

- 一路 SPI 主机，模式 0，8 位，MSB first。
- 一个 BUSY 输入 GPIO。
- 三个输出 GPIO：RES、DC、CS。
- 一个可用的毫秒 delay 和 tick 来源。

当前 elinktest 的 SPI 配置是保守值，目的是先让首刷稳定跑通。

### 4.2 保留 device 层

正常情况下，直接复制这两个文件：

- `device/epd_gdey0213b74.h`
- `device/epd_gdey0213b74.c`

不要在这层写 HAL 句柄、GPIO 宏名或板级端口。

### 4.3 重写 platform 层

需要重点改的是这两个文件：

- `platform/stm32_gdey0213b74.h`
- `platform/stm32_gdey0213b74.c`

你至少要完成下面这些映射：

- `spi_handle`
- `busy_port` / `busy_pin`
- `reset_port` / `reset_pin`
- `dc_port` / `dc_pin`
- `cs_port` / `cs_pin`
- `spi_timeout_ms`

同时保证这些回调语义不变：

- `spi_write()`：失败必须返回，不能无限卡住。
- `read_busy()`：忙返回 1，空闲返回 0。
- `set_cs()` / `set_dc()` / `set_reset()`：非零表示高电平。
- `delay_ms()`：单位是毫秒。
- `get_tick_ms()`：返回单调递增的毫秒 tick。

### 4.4 复用或替换 app 层

如果你还只是做首个点亮验证，直接复用：

- `app/epd_hello_world.h`
- `app/epd_hello_world.c`

这个 app 会画三类信息：

- 边框
- 左上角黑方块
- 居中的 Hello World
- 底部一行 tick 快照

如果你后续要换成真实业务界面，通常只改 app 层。

### 4.5 接回 main 和工程文件

如果你用 CubeMX 生成 `Core/`，只在 `USER CODE` 区里做两件事：

1. 包含 app 头文件。
2. 在初始化后调用 `epd_hello_world_start()` 或你的新 app 入口。

如果你用 Keil，还要把新增的 `.c` 文件手动加到工程分组里。

## 5. 移植到非 STM32 平台时的最小改动面

如果你换到别的 MCU 或 SDK，只要能提供下面这 7 个能力，`device/` 理论上都可以不改：

- SPI 写
- 读 BUSY
- 写 CS
- 写 DC
- 写 RESET
- 毫秒延时
- 毫秒 tick

这也是当前驱动把硬件能力全部放进 `epd_gdey0213b74_io_t` 的原因。

## 6. 最容易踩坑的地方

### 6.1 不要随便改 `0x11`

当前代码使用 `0x11 = 0x01`，并配合旋转 270 度的像素映射。

如果你把它改成 `0x03`，同时又不改 `epd_gdey0213b74_set_pixel()` 的地址变换，文字和图形大概率会镜像、倒置或错位。

### 6.2 每次整屏写图前都要重设 `0x4E` 和 `0x4F`

当前代码已经在 `epd_gdey0213b74_display_frame()` 里补齐了这一点。

不要假设初始化阶段设置过一次游标，后续所有刷新都还能从那个地址开始。

### 6.3 LUT 加载不要省

当前初始化已按手册步骤 4 执行 `0x22 = 0xB1` → `0x20` → 等待 BUSY，从 OTP 加载波形 LUT。如果新工程里把这一步漏掉，常见现象就是 SPI 看起来正常，但屏没有完整刷新动作或花屏。

### 6.4 BUSY 轮询必须带超时

不要用死循环等 BUSY。

当前 `device/` 里已经做了超时保护。若硬件连线有误，代码会返回错误，不会一直卡死在 while 里。

### 6.5 tick 文本只是一次快照

当前 app 只在上电时整刷一次，所以屏上的 tick 是“绘图时刻的毫秒值”，不是实时变化计时器。

如果你需要实时更新时间，必须设计新的刷新策略，而不是指望深睡眠后的这张图自己变化。

## 7. 建议的上板验证顺序

建议每次移植后按这个顺序验：

1. 先看 Keil 是否编译通过。
2. 上板后先看 BUSY 是否在初始化和刷新阶段出现高电平忙状态。
3. 再看屏上是否能出现边框和左上角黑块。
4. 然后看 Hello World 是否方向正确。
5. 最后看底部 tick 数字是否可读。

如果边框和黑块都不对，优先查方向和 RAM 地址。

如果 SPI 波形有、BUSY 没反应，优先查电源、BS1、RES、GDR、RESE 和屏座焊接。

## 8. 文件替换建议

### 同型号屏，换 MCU

- 保留 `device/`
- 保留 `app/`
- 重写 `platform/`
- 重新接回 `main.c`

### 同 MCU，换别的屏控制器

- 重写 `device/`
- 视接口兼容程度调整 `app/`
- `platform/` 大部分可复用

### 同板子，只改业务界面

- 保留 `device/`
- 保留 `platform/`
- 只改 `app/`

## 9. 当前版本的推荐定位

当前版本最适合做这三件事：

- 首次点亮
- GPIO / SPI / BUSY 连线确认
- 后续业务界面的稳定基线

它不是完整图形库，也不是局刷框架。

如果后续要上局部刷新、定时更新或触摸交互，建议继续在 `app/` 和 `device/` 外围逐步扩展，不要把业务逻辑再塞回 `Core/`。
