# GDEY029T94-FL03 原厂实例代码调用流程

## 1. 文档目的

本文记录 `S-GDEY029T94-FL03原厂实例代码` 的源码结构、调用流程和墨水屏驱动方式。

分析对象是：

- 屏幕：GDEY029T94-FL03
- 分辨率：296 × 128
- 接口：4 线 SPI
- 控制器：SSD1680 兼容方案
- 原厂 MCU 示例：STM32F103，标准外设库，软件模拟 SPI

本文结合原厂实例代码和 `GDEY029T94-FL03.pdf` 编写。原厂工程是演示工程，不是可直接放入当前 STM32L471 工程的最终驱动。

## 2. 文件分工

原厂工程中与屏幕直接相关的文件如下：

```text
USER/main.c
    演示入口，组织全刷、快刷、局刷、GUI 和休眠流程

HARDWARE/EPD/Display_EPD_W21.h
    分辨率、显存大小和公开接口声明

HARDWARE/EPD/Display_EPD_W21.c
    屏幕初始化、BUSY 等待、显存写入、刷新、局刷和深睡眠

HARDWARE/EPD/Display_EPD_W21_spi.h
    GPIO 宏、BUSY 读取宏和底层接口声明

HARDWARE/EPD/Display_EPD_W21_spi.c
    GPIO 初始化、软件 SPI、命令发送和数据发送

HARDWARE/EPD/Ap_29demo.h
    原厂演示图片、数字图片和局刷背景图

HARDWARE/GUI/*
    画布、点线面、字符和数字绘制功能

HARDWARE/Fonts/*
    字体数据
```

核心分层可以概括为：

```text
main()
  └─ EPD_GPIO_Init()
       └─ GPIO 初始化
  └─ EPD_HW_Init() / EPD_HW_Init_Fast()
       └─ 硬件复位
       └─ 软件复位 0x12
       └─ 初始化 SSD1680 控制寄存器
       └─ Epaper_READBUSY()
  └─ EPD_WhiteScreen_ALL() / EPD_Dis_Part_Time()
       └─ 写 RAM 命令 0x24 或 0x26
       └─ EPD_Update() / EPD_Part_Update()
            └─ 更新控制 0x22
            └─ 激活更新 0x20
            └─ 等待 BUSY 结束
  └─ EPD_DeepSleep()
       └─ 深睡眠命令 0x10
```

## 3. main.c 总体调用流程

### 3.1 上电初始化

`main()` 先调用：

```c
delay_init();
NVIC_Configuration();
EPD_GPIO_Init();
```

其中：

- `delay_init()` 初始化原厂延时模块。
- `NVIC_Configuration()` 设置 STM32F1 的中断分组。
- `EPD_GPIO_Init()` 初始化屏幕 GPIO。

屏幕 GPIO 初始化完成后，程序进入演示循环。

### 3.2 全屏刷新流程

原厂主流程为：

```c
EPD_HW_Init();
EPD_WhiteScreen_ALL(gImage_1);
EPD_DeepSleep();
delay_s(2);
```

调用关系如下：

```text
EPD_HW_Init()
  ├─ RES 拉低，延时 10 ms
  ├─ RES 拉高，延时 10 ms
  ├─ 等待 BUSY 变低
  ├─ 发送 SWRESET：0x12
  ├─ 等待 BUSY 变低
  ├─ 配置 Gate、RAM 地址和边框波形
  └─ 等待 BUSY 变低

EPD_WhiteScreen_ALL(image)
  ├─ 发送写 RAM 命令：0x24
  ├─ 连续发送 EPD_ARRAY 字节
  └─ 调用 EPD_Update()
       ├─ 发送 0x22，写入 0xF7
       ├─ 发送 0x20
       └─ 等待 BUSY 变低

EPD_DeepSleep()
  ├─ 发送 0x10
  ├─ 写入 0x01
  └─ 延时 100 ms
```

原厂注释要求每次全屏刷新前重新初始化，刷新完成后进入深睡眠。

### 3.3 快速刷新流程

```c
EPD_HW_Init_Fast();
EPD_WhiteScreen_ALL_Fast(gImage_2);
EPD_DeepSleep();
```

快速刷新初始化主要做三件事：

1. 硬件复位和软件复位。
2. 读取内部温度传感器配置。
3. 通过 `0x22`、`0x20` 和 `0x1A` 加载快速刷新温度参数。

快速刷新写 RAM 的方式仍然是 `0x24`，区别主要在更新控制寄存器：

```text
全刷：0x22 -> 0xF7
快刷：0x22 -> 0xC7
局刷：0x22 -> 0xFF
```

这些控制值是原厂针对本屏波形和版本给出的配置，不应脱离本屏手册和实测结果直接套到其他屏幕。

### 3.4 局部刷新流程

局刷演示先初始化并写入背景图：

```c
EPD_HW_Init();
EPD_SetRAMValue_BaseMap(gImage_basemap);
EPD_Dis_Part_Time(...);
EPD_DeepSleep();
```

`EPD_SetRAMValue_BaseMap()` 的流程是：

```text
0x24 + 全屏背景数据
0x26 + 全屏背景数据
EPD_Update()
```

其中 `0x26` 用于保存另一份 RAM 数据。原厂注释明确要求保留背景图步骤，否则局刷可能不稳定。

`EPD_Dis_Part_Time()` 是一个面向时钟的演示接口。它固定更新 5 个区域，内部依次调用 5 次 `EPD_Dis_Part_RAM()`，最后调用一次 `EPD_Part_Update()`。

```text
EPD_Dis_Part_Time()
  ├─ EPD_Dis_Part_RAM(A)
  ├─ EPD_Dis_Part_RAM(B)
  ├─ EPD_Dis_Part_RAM(C)
  ├─ EPD_Dis_Part_RAM(D)
  ├─ EPD_Dis_Part_RAM(E)
  └─ EPD_Part_Update()
```

### 3.5 GUI 绘制流程

GUI 演示被 `#if 0` 关闭，默认不参与运行。启用后流程为：

```c
Paint_NewImage(BlackImage, EPD_WIDTH, EPD_HEIGHT, 270, WHITE);
Paint_SelectImage(BlackImage);
EPD_HW_Init_GUI();
Paint_Clear(WHITE);
Paint_DrawPoint(...);
Paint_DrawLine(...);
Paint_DrawRectangle(...);
Paint_DrawCircle(...);
EPD_Display(BlackImage);
EPD_DeepSleep();
```

GUI 层只负责修改 `BlackImage` 缓冲区，真正发送给屏幕的是 `EPD_Display()`。

## 4. 屏幕驱动核心

### 4.1 分辨率和显存

头文件定义：

```c
#define EPD_WIDTH   128
#define EPD_HEIGHT  296
#define EPD_ARRAY   EPD_WIDTH * EPD_HEIGHT / 8
```

因此：

```text
X 方向：128 像素
X RAM：128 / 8 = 16 字节
Y 方向：296 行
总显存：16 × 296 = 4736 字节
```

原厂代码把 128 像素作为 X 方向，把 296 行作为 Y 方向。这里的 `EPD_WIDTH` 并不是物理规格表中写在前面的 296，而是源码坐标系统中的横向像素数。

### 4.2 初始化寄存器

`EPD_HW_Init()` 使用的主要命令如下：

| 命令 | 作用 | 原厂参数 |
| --- | --- | --- |
| `0x12` | 软件复位 | 无参数 |
| `0x01` | Driver Output Control | `0x27, 0x01, 0x00` |
| `0x11` | Data Entry Mode | `0x01` |
| `0x44` | 设置 X RAM 起止地址 | `0x00, 0x0F` |
| `0x45` | 设置 Y RAM 起止地址 | `0x27, 0x01, 0x00, 0x00` |
| `0x3C` | Border Waveform | `0x05` |
| `0x21` | Display Update Control | `0x00, 0x80` |
| `0x18` | 温度传感器选择 | `0x80` |
| `0x4E` | 设置当前 X 地址 | `0x00` |
| `0x4F` | 设置当前 Y 地址 | `0x27, 0x01` |

`0x27, 0x01` 是十进制 295，表示 Y 地址范围 `0~295`，对应 296 行。

PDF 的典型工作流程也要求按类似顺序完成：

```text
硬件复位
软件复位 0x12
配置 Gate Driver 0x01
配置 RAM 0x11、0x44、0x45
配置边框 0x3C
加载波形 0x22、0x20
设置 RAM 地址 0x4E、0x4F
写入图像 0x24、0x26
刷新 0x22、0x20
等待 BUSY 变低
进入深睡眠 0x10
```

### 4.3 BUSY 等待

原厂定义：

```c
#define isEPD_W21_BUSY GPIO_ReadInputDataBit(GPIOE, GPIO_Pin_13)
```

等待函数逻辑为：

```c
while (1)
{
    if (isEPD_W21_BUSY == 0)
        break;
}
```

也就是：

```text
BUSY = 1：屏幕忙，禁止发送命令
BUSY = 0：屏幕空闲，可以继续操作
```

这与 PDF 的说明一致。原厂代码没有超时机制，BUSY 断线或引脚悬空时可能永久卡死。移植到当前工程时必须增加超时返回和错误状态。

### 4.4 命令和数据发送

底层发送分为两个接口：

```c
EPD_W21_WriteCMD(command);
EPD_W21_WriteDATA(data);
```

两者的差别只有 D/C 电平：

```text
WriteCMD：CS 低，D/C 低，发送一个字节，CS 高
WriteDATA：CS 低，D/C 高，发送一个字节，CS 高
```

软件 SPI 的发送顺序是 MSB first：

```text
取最高位
设置 MOSI
拉高 SCK
拉低 SCK
左移数据
重复 8 次
```

原厂代码的 SPI 实现位于 `Display_EPD_W21_spi.c`，没有使用 STM32 SPI 外设。

## 5. GPIO 和 SPI 连接

原厂示例的 GPIO 如下：

| 信号 | 原厂引脚 | 有效电平或说明 |
| --- | --- | --- |
| CS | PD8 | 低有效 |
| SCK | PD9 | SPI 时钟 |
| MOSI | PD10 | SPI 数据 |
| D/C | PE15 | 低命令，高数据 |
| RES | PE14 | 低有效 |
| BUSY | PE13 | 高忙，低空闲 |
| LED | PE12 | 前置光源控制 |

当前桌面时钟工程的屏幕连接记录为：

| 信号 | 当前引脚 | 当前宏或备注 |
| --- | --- | --- |
| SPI2 SCK | PB10 | AF5 |
| SPI2 MOSI | PC3 | AF5 |
| CS | PB2 | `CS2_Pin`，GPIO 手动控制 |
| D/C | PB1 | GPIO |
| RES | PB0 | 低有效 |
| BUSY | PC5 | 高忙 |

因此只能复用原厂的命令时序，不能复用原厂 GPIO 宏和 GPIO 初始化代码。

## 6. 局刷坐标和数据限制

原厂局刷函数使用以下计算：

```c
x_start = x_start / 8;
x_end = x_start + PART_LINE / 8 - 1;
y_start = y_start;
y_end = y_start + PART_COLUMN - 1;
```

这说明原厂接口存在以下隐含要求：

- X 起点按 8 像素对齐。
- X 方向区域长度必须是 8 的倍数。
- 传入的数据按区域逐字节排列。
- Y 地址按行计算。
- 没有做坐标越界检查。

`EPD_Dis_Part_RAM()` 还会执行：

```c
y_start = y_start - 1;
```

这是原厂时钟演示坐标体系留下的偏移。当前驱动不应直接保留，否则 `y_start == 0` 时会发生无符号下溢。建议当前工程统一采用 0 基坐标，并在接口中检查：

```text
x_start % 8 == 0
width % 8 == 0
x_start + width <= 128
y_start + height <= 296
```

## 7. 原厂代码中可复用和不可直接复用的内容

### 7.1 可以复用

- SSD1680 命令顺序。
- `0x01` 对应 296 行的配置。
- `0x44`、`0x45` 的 RAM 地址范围。
- `0x24` 写黑白 RAM 的方式。
- `0x26` 配合局刷保存背景的方式。
- `0x22`、`0x20` 的刷新流程。
- 深睡眠命令 `0x10`。
- 全刷、快刷、局刷三种更新思路。

### 7.2 不能直接复用

- STM32F1 的 `stm32f10x.h` 和标准外设库调用。
- 原厂 PD、PE 端口宏。
- 软件 SPI 时序实现。
- 忙等待函数。
- 无边界检查的局刷接口。
- `y_start - 1` 坐标偏移。
- GUI、字体和演示图片。
- 原厂延时函数 `delay_xms()`。

## 8. 移植到 STM32L471 的建议结构

建议把原厂代码拆成三层：

```text
app/
  app_epd_demo.c
    组织清屏、显示测试图和进入休眠

Device/
  epd_ssd1680.c
  epd_ssd1680.h
    保存命令字、初始化流程、显存地址、刷新流程和状态机

Platform/
  stm32_epd.c
  stm32_epd.h
    使用 SPI2、GPIO、HAL_GetTick 和 HAL_Delay
```

Device 层建议只依赖抽象接口：

```text
spi_write()
set_cs()
set_dc()
set_reset()
read_busy()
delay_ms()
get_tick_ms()
```

Platform 层再把这些接口绑定到：

```text
hspi2
CS2_Pin
DC_Pin
RES_Pin
BUSY_Pin
```

### 8.1 第一阶段验证顺序

建议按以下顺序验证：

1. 只初始化 GPIO 和 SPI2。
2. 硬件复位后读取并记录 BUSY 电平。
3. 初始化屏幕并等待 BUSY 结束。
4. 写入 4736 字节全白数据。
5. 写入 4736 字节全黑数据。
6. 写入黑白条纹测试图。
7. 最后再加入局刷和深睡眠。

## 9. 风险记录

### 9.1 BUSY 无限等待

原厂代码没有超时。当前工程必须改成有限等待，否则屏线断开、BUSY 悬空或屏幕供电异常时，主循环会永久停止。

### 9.2 SPI NSS 配置

当前工程使用硬件 SPI2、软件片选。需要确认 SPI 的 NSS 脉冲配置不会干扰手动 CS 时序。

### 9.3 局刷残影

PDF 和原厂示例都要求局刷若干次后使用全刷清除残影。时钟应用不能无限局刷而不维护局刷计数。

### 9.4 深睡眠后的状态

深睡眠会关闭屏幕控制器内部电源。下一次显示前需要重新初始化，不能假设之前的 RAM 地址和波形配置仍然有效。

### 9.5 原厂演示代码的主循环

原厂 `main()` 在演示流程结束后进入永久 `while(1)`。这适合一次性展示，不适合当前桌面时钟的周期任务。当前应用应由 `app` 层按时间调度显示更新，不能照搬原厂主循环。
