## 3. 原厂默认程序到底做了什么

### 3.1 从最外层看

`main()` 先完成延时、中断分组和屏幕 GPIO 初始化，然后只运行一轮演示：

```text
启动
  -> GPIO 初始化
  -> 黑白全刷一张图
  -> 深睡眠
  -> 快刷第二张图
  -> 深睡眠
  -> 写入局刷背景图
  -> 执行 6 次时钟数字局刷
  -> 深睡眠
  -> 全屏清白
  -> 深睡眠
  -> 永久停在 while(1)
```

AXF 反汇编和链接调用图确认最终镜像中的默认调用顺序为：

```text
EPD_HW_Init
EPD_WhiteScreen_ALL(gImage_1)
EPD_DeepSleep

EPD_HW_Init_Fast
EPD_WhiteScreen_ALL_Fast(gImage_2)
EPD_DeepSleep

EPD_HW_Init
EPD_SetRAMValue_BaseMap(gImage_basemap)
EPD_Dis_Part_Time(...) x 6
EPD_DeepSleep

EPD_HW_Init
EPD_WhiteScreen_White
EPD_DeepSleep
永久循环
```

四灰阶、GUI、180 度显示和全屏局刷演示由 `#if 0` 关闭，不属于默认运行路径。

### 3.2 一次刷新的基本结构

无论全刷、快刷还是局刷，都可以拆成五步：

1. 复位屏幕。
2. 写控制器初始化寄存器。
3. 把图像数据写入控制器 RAM。
4. 发送刷新命令并等待 BUSY 结束。
5. 发送深睡眠命令。

最重要的区别是更新控制值：

| 模式     | `0x22` 数据 | 随后命令 |
| -------- | ------------- | -------- |
| 黑白全刷 | `0xF7`      | `0x20` |
| 快刷     | `0xC7`      | `0x20` |
| 局刷     | `0xFF`      | `0x20` |

深睡眠使用：

```text
命令 0x10
数据 0x01
```

### 3.3 显存和坐标

屏幕物理分辨率是 296 x 128。原厂驱动按控制器 RAM 的方向定义：

```text
X：128 像素，也就是每行 16 字节
Y：296 行，地址 0 到 295
单色全屏缓冲区：128 / 8 x 296 = 4736 字节
```

正常黑白初始化中的关键参数为：

| 命令     | 数据                       | 含义                       |
| -------- | -------------------------- | -------------------------- |
| `0x01` | `0x27, 0x01, 0x00`       | 296 条 Gate 线，末地址 295 |
| `0x11` | `0x01`                   | RAM 数据进入方向           |
| `0x44` | `0x00, 0x0F`             | X 地址范围 0 到 15 字节    |
| `0x45` | `0x27, 0x01, 0x00, 0x00` | Y 地址范围 295 到 0        |
| `0x4E` | `0x00`                   | 当前 X 地址                |
| `0x4F` | `0x27, 0x01`             | 当前 Y 地址 295            |

### 3.4 SPI 和 BUSY

目标接口要求：

- 四线 SPI
- 8 位数据
- MSB first
- SPI Mode 0
- 写入时钟不高于数据手册给出的 20 MHz 上限
- BUSY 高电平表示忙，低电平表示可继续
- CS 低有效
- D/C 低表示命令，高表示数据
- RESET 低有效

原厂例程使用 GPIO 模拟 SPI。移植时只保留“命令、数据和时序语义”，不复制 STM32F103 GPIO 宏和空循环延时。

## 5. 编译成功后仍然存在的源码风险

### 5.1 BUSY 可能永久卡住

`Epaper_READBUSY()` 使用无限循环，没有超时。如果屏幕未上电、BUSY 接错、控制器异常或电平一直为高，程序会永远停住。

移植要求：所有 BUSY 等待必须使用毫秒时基和超时值，超时后返回明确错误。

### 5.2 局刷输入没有边界检查

原厂局刷接口没有完整检查：

- 坐标是否在屏幕内
- 宽高是否为零
- X 是否满足字节对齐要求
- `x + width`、`y + height` 是否越界
- 宽高乘法是否溢出
- 图像缓冲区长度是否足够

移植要求：公共 API 在发送命令前完成全部检查，非法输入不能触碰硬件。

### 5.3 `y_start == 0` 会下溢

`EPD_Dis_Part_RAM()` 中存在：

```c
y_start = y_start - 1;
```

如果传入 0，无符号坐标会下溢。新驱动不能照搬这个接口和运算。

### 5.4 GUI 初始化的 Gate 数异常

`EPD_HW_Init_GUI()` 使用 `EPD_HEIGHT + 46`，也就是 342 条 Gate 线；屏幕正常 MUX 是 296。当前没有足够证据解释这 46 行的用途。

处理方式：首轮移植不实现该路径。后续只有在数据手册、厂家说明或逻辑分析和实屏测试能够证明时，才加入 GUI 专用初始化。

### 5.5 GUI 边界判断有越界风险

`GUI_Paint.c` 使用：

```c
if (X > Paint.WidthMemory || Y > Paint.HeightMemory)
```

有效下标的上限应是 `WidthMemory - 1` 和 `HeightMemory - 1`。等于宽或高时也应拒绝，所以条件应按 `>=` 设计。

### 5.6 演示程序不是产品任务

原厂 `main()` 演示一次后永久停止。它没有电源域管理、超时上报、重试策略、业务刷新调度或低功耗任务协作。它只能作为协议参考。

### 6.1 照片方向定位与当前代码修正

本次实物照片以照片 1 为正常查看方向，屏幕排线在右侧。照片 2 是把屏幕在面内机械旋转 180 度后的结果，不能用来替代软件坐标验证。

从照片和运行现象可以确认：

- 右侧数字持续变化，说明逻辑左右顺序正确，秒位仍在右侧；当前不是整幅图水平镜像。
- 数字 `4` 上下倒置，说明主要问题是上下方向镜像。机械旋转屏幕只会把这个错误转换成另一条轴上的镜像，不能修复它。
- 当前帧缓冲区使用 MSB-first 位打包，与原厂 `Paint_SetPixel()` 一致；照片没有显示出单字节 bit-reverse 才会产生的局部字符镜像。
- `main.c` 调用 `epd_bringup_run_clock()` 后，首帧全刷、后续秒变化进入局刷，因而“4 到 2 乱飞”必须与静态坐标错误分开验证。

原来的逻辑到物理映射是：

```c
physical_x = logical_y;
physical_y = 295 - logical_x;
```

它等价于原厂 GUI 的 `ROTATE_270`。目标驱动采用的是普通 296 Gate 初始化，因此当前应用层增加对原生 128 像素轴的镜像，修正为：

```c
physical_x = 127 - logical_y;
physical_y = 295 - logical_x;
```

这次修正不改变 `0x11`、`0x44`、`0x45`、`0x4E`、`0x4F`，也不启用 `EPD_HW_Init_180()` 或 `EPD_HEIGHT + 46` 的 342 Gate GUI 路径。180 度初始化必须和完整的 RAM 窗口、计数器及数据进入方向成套验证，不能用来替代单轴坐标修正。

秒区局刷窗口也必须跟随同一变换。当前窗口使用物理 `x=40,width=56`、`y=8,height=84`，覆盖修正后秒数字的完整短轴范围并满足 8 像素字节对齐。

应用层保留两个编译期开关：

```c
#define EPD_CLOCK_DIAGNOSTIC_PATTERN 0U
#define EPD_CLOCK_DIAGNOSTIC_FORCE_FULL 0U
```

正常运行保持 `EPD_CLOCK_DIAGNOSTIC_FORCE_FULL=0`，使用首帧全刷、秒级局刷和分钟快刷；需要隔离局刷残影时临时置为 `1`，每秒整屏刷新。需要检查四角方向图时将 `EPD_CLOCK_DIAGNOSTIC_PATTERN` 置为 `1`，诊断完成后恢复为 `0`。

方向验收图必须包含：四角不同形状、非对称箭头和 `0123456789`。照片 1 方向下的通过条件是：顶部/底部不交换，左右不交换，数字顺序可读，`4` 不倒置，且没有字节内局部镜像。

动态验收至少覆盖 `3->4`、`4->5`、`4->2`、`9->0` 和分钟进位。若强制全刷时画面稳定而局刷时出现残影，再单独检查局刷窗口地址、数据行序、`0x24/0x26` 背景基准以及 `0x22=0xFF` 更新流程。

### 6.2 频繁全刷的代码证据

本次现场看到的整屏闪烁来自清残影阈值，不是坐标变换或诊断强制全刷：

1. `epd_bringup_run_clock()` 首次显示调用 `epd_clock_set_background()`，这只产生一次首帧全刷。
2. 同一分钟的秒变化调用 `epd_clock_partial_refresh()`，设备层将 `refreshes_since_full` 加一。
3. 当计数达到 `EPD_GDEY029T94_CLEANUP_INTERVAL` 时，局刷函数立即使用保存的完整背景图调用 `epd_gdey029t94_full_refresh()`。
4. 分钟变化调用快刷，快刷也共享同一计数器；因此阈值不能按“调用次数”误认为只影响局刷。

此前阈值为 `5U`，时钟序列就是“首帧全刷、4 次局刷、第 5 次后全刷”，约每 5 秒重复；随后改为 `30U`，现场仍觉得闪烁明显，因此当前源码默认改为 `120U`。`EPD_CLOCK_DIAGNOSTIC_FORCE_FULL` 仍为 `0U`，Keil 工程没有覆盖该宏。若现场仍每秒整屏刷新，应先核对烧录的 HEX 身份，或检查编译参数是否外部定义了诊断宏。

### 6.3 全刷间隔和数字字形的当前配置

全刷清残影阈值位于：

```text
elinkTest/device/epd_gdey029t94.h
    EPD_GDEY029T94_CLEANUP_INTERVAL    120U
```

它统计成功的快刷和局刷次数。时钟每秒只改变秒区时，通常一次局刷对应一秒；分钟变化走一次整帧快刷，也会计入同一个计数器。首帧 `epd_gdey029t94_set_background()` 为建立 `0x24/0x26` 基准而执行的全刷不受该阈值控制。

数字绘制仍在应用层，但不再使用原先的 5 x 7 手写字模：

```text
elinkTest/app/epd_bringup.c
    EPD_CLOCK_GLYPH_W       11U
    EPD_CLOCK_GLYPH_H       15U
    EPD_CLOCK_SCALE         3U
```

```c
physical_x = 127 - logical_y;
```

当前秒区仍落在原有 `x=40,width=56,y=8,height=84` 局刷窗口内；窗口覆盖完整的两位秒数字，没有改变设备层接口或初始化寄存器。

```text
app/
```

```c
typedef struct {

                         const uint8_t *data,
                         uint32_t length,
                         uint32_t timeout_ms);
    int32_t (*read_busy)(void *ctx, uint8_t *busy_level);
    void (*set_cs)(void *ctx, uint8_t level);
    void (*set_dc)(void *ctx, uint8_t level);
    void (*set_reset)(void *ctx, uint8_t level);
    void (*set_power)(void *ctx, uint8_t enabled);
    void (*delay_ms)(void *ctx, uint32_t delay_ms);
    uint32_t (*get_tick_ms)(void *ctx);
    void *ctx;
} epd_io_t;
```

```c
typedef enum {
```

```c
epd_status_t epd_gdey029t94_power_on(epd_gdey029t94_t *dev);
epd_status_t epd_gdey029t94_full_refresh(epd_gdey029t94_t *dev,

```

首轮可以只实现 `init`、`power_on`、`full_refresh` 和 `sleep`，其余函数在第二阶段加入。

## 10. 实现规则

### 10.1 SPI

- Mode 0、8 bit、MSB first。
- CS 由平台层 GPIO 手动控制。
- 每次命令或连续数据块保持清楚的 CS 边界。
- 首次联调使用较低速率，例如几百 kHz 到 1 MHz；波形正确后再逐步提高。
- 任何速率都不能超过 20 MHz 写入上限。
- 检查 CubeMX 的 NSS 设置，避免硬件 NSS 脉冲干扰手动 CS。

### 10.2 RESET 和 BUSY

- RESET 的低、高保持时间先按原厂示例的 10 ms 起步，再用手册和波形确认。
- `wait_ready(timeout_ms)` 处理计时回绕，不能使用无限循环。
- 超时日志至少记录操作阶段、超时值和最后一次 BUSY 电平。
- BUSY 高表示忙。上电后先记录静态电平，避免接线错误被误认为屏幕空闲。

### 10.3 初始化

第一阶段严格使用已确认的 296 Gate 黑白初始化。命令表保存在一个只读常量表或清晰的函数中，并为每个命令写名字。

初始化成功的判断不是“命令发完了”，而是：

1. SPI 调用均成功。
2. 必要的 BUSY 等待在超时内结束。
3. 后续固定测试图能够正确显示。

### 10.4 全刷

- 只接受长度至少为 4736 字节的单色缓冲区。
- 写 RAM 命令为 `0x24`。
- 写完 4736 字节后，发送 `0x22 = 0xF7` 和 `0x20`。
- 等待 BUSY 结束后才允许休眠或下一次操作。

### 10.5 快刷

- 使用原厂快刷初始化顺序和温度相关命令作为起点。
- 刷新控制使用 `0x22 = 0xC7`，随后发送 `0x20`。
- 记录刷新时间和残影。不能只凭画面“变了”就判断通过。

### 10.6 局刷

局刷前检查：

- `rect` 和图像指针非空。
- `width`、`height` 非零。
- 矩形完全落在 128 x 296 的控制器坐标范围内。
- X 起点和宽度符合 8 像素打包规则，或由驱动安全扩展到字节边界。
- 计算 `bytes_per_row * height` 前检查溢出。
- `image_length` 足够。
- 不使用 `y_start - 1` 这类会在零点下溢的写法。

第一次局刷前先按原厂思路向 `0x24` 和 `0x26` 写入同一张全屏背景，再执行一次全刷。局刷使用 `0x22 = 0xFF` 和 `0x20`。

### 10.7 电源和深睡眠

建议顺序：

```text
开启屏幕电源域
  -> 等待电源稳定
  -> 配置 GPIO 和 SPI 空闲电平
  -> RESET
  -> 初始化
  -> 写 RAM
  -> 刷新并等待 BUSY
  -> 发送 0x10 / 0x01 深睡眠
  -> 等待命令完成所需时间
  -> 将控制脚置为板级安全状态
  -> 按硬件设计决定是否关闭屏幕电源域
```

关电前要确认屏幕已经结束刷新。电源域关闭后的 GPIO 状态要避免从 MCU 反向供电。

## 11. 分阶段实施与验收

### 阶段 0：恢复目标工程

交付：

- 可打开的 `.ioc` 和 Keil 工程
- 干净构建日志
- 目标工程产物哈希
- 已核对的屏幕引脚和电源表

通过条件：工程可重复构建，新增文件进入编译和链接，硬件连接没有待确认项。

### 阶段 1：平台层通路

工作：

- 实现 GPIO、SPI、delay、tick、power 回调
- 发送已知命令和小段数据
- 观察 CS、SCK、MOSI、D/C、RESET、BUSY

通过条件：逻辑分析仪显示 Mode 0、MSB first、D/C 和 CS 边界正确；故意断开 BUSY 或保持忙状态时能超时返回。

### 阶段 2：黑白全刷

工作：

- 实现 296 Gate 初始化
- 显示全白、全黑、棋盘格、边框和方向图
- 刷新后进入深睡眠

通过条件：至少连续冷启动 10 次显示方向和边界正确；没有卡死；每次刷新后 BUSY 能回到空闲；镜像与构建身份可追溯。

### 阶段 3：快刷

工作：

- 实现快刷初始化和更新
- 对比全刷和快刷时间
- 记录不同画面变化下的残影

通过条件：快刷稳定完成；刷新时间有测量记录；连续刷新不会造成永久卡死或明显错误行列。

### 阶段 4：局刷

工作：

- 建立背景 RAM
- 更新四角、边缘、跨字节和中间小块
- 验证非法参数和缓冲区长度
- 执行多轮局刷后全刷清残影

通过条件：边界用例无越界和下溢；错误输入不发送 SPI；局刷区域、方向和数据长度正确。

### 阶段 5：低功耗和产品接入

工作：

- 测量刷新、深睡眠和断电状态电流
- 接入 RTC 页面和刷新调度
- 定义错误恢复、重试和全刷策略

通过条件：功耗和刷新频率满足 `totalPLAN.md`；异常后系统可恢复；屏幕任务不阻塞其他产品功能。

## 13. 不应直接复制的原厂内容

- STM32F103 标准外设库初始化。
- PE13、PB5、PB6、PB7、PB8 等原厂板 GPIO 宏。
- GPIO 模拟 SPI。
- 依赖 CPU 频率的空循环延时。
- 没有超时的 `Epaper_READBUSY()`。
- 不带长度的图像指针接口。
- 没有检查的局刷坐标算法。
- `y_start = y_start - 1`。
- 未解释的 342 Gate GUI 初始化。
- 原厂一次性演示 `main()`。
- 默认关闭且未经验证的 GUI、字体和四灰阶代码。

可以复用的是寄存器命令含义、已确认的 296 Gate 初始化参数、刷新控制值、背景 RAM 思路和深睡眠要求。
