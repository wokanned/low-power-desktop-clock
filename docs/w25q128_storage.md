# W25Q128 存取模块

更新日期：2026-10-27。文档入口见 [文档导航](README.md)，整机进度见 [totalPLAN.md](totalPLAN.md#当前开发状态2026-10-27)。

本模块为板上的 W25Q128JV 外部 SPI NOR Flash 提供阻塞式存取接口。设备层位于 `device/flash_w25q128.*`，STM32 HAL 适配位于 `platform/stm32_w25q128.*`，启动自检和任务归属位于 `app/storage.*`。

驱动、启动自检、时制配置和非空扇区扫描已接入；包含天气与 TIME 的默认黑白完整 Keil 构建已通过，最新镜像尚未烧录，本模块仍无目标板验收记录。当前未实现文件系统、字库/图标资源管理、天气持久缓存或循环日志。下文构建与主机测试记录只适用于各自记录的版本。

## 硬件绑定

- SPI1，模式 0，8 位、MSB first，当前 CubeMX 配置为 1.25 MHz。
- SCK=PA5，MISO=PA6，MOSI=PA7，CS=PA4（`CS1`）。
- `storage_start()` 在 `MX_FREERTOS_Init()` 创建 `storageTask` 前绑定平台资源。适配层使用一个静态互斥锁保护完整 SPI 命令序列，接口要求任务上下文。
- 设备层不包含 HAL。所有总线、延时、时间和锁操作由 `w25q128_ctx_t` 注入。

## API 行为

`w25q128_init()` 等待上电编程禁止时间，发送 `0xAB` 退出掉电，再等待空闲，校验 JEDEC ID `EF 40 18`，并读取 SR1/SR2/SR3。`read`、`program`、扇区/32 KiB/64 KiB/整片擦除都检查范围和参数，并在操作后轮询 WIP。轮询使用单调的 32 位毫秒差值，所有等待都有上限。

`program` 不会自动擦除。它按 256 字节页边界拆分，先检查目标字节是否存在 0 到 1 的非法变化，写入后逐页读回校验。检测到需要擦除时返回 `W25Q128_ERROR_NEEDS_ERASE`。

`update` 用调用者提供的至少 4096 字节 `p_scratch` 完成扇区读、合并、擦除和重写。缓存只在调用期间使用，不能与输入数据重叠。跨扇区更新会逐扇区处理；内容没有变化时跳过擦除和编程。掉电发生在擦除或重写中间时，扇区可能只完成部分更新，模块不声明原子提交或掉电一致性，上层记录格式需要自行设计恢复策略。

状态寄存器中的 BP、CMP 或 WPS 保护配置会使所有修改操作返回 `W25Q128_ERROR_PROTECTED`。模块不会自动解锁、写状态寄存器、修改 OTP 或改变保护策略。检测到 SUS 挂起状态也会返回忙错误。

## 启动自检

默认 `STORAGE_BOOT_TEST_ENABLE=1`。独立的静态 `storageTask` 每次启动只执行一次：

1. 初始化、读取 ID 和三个状态寄存器，加载末尾双扇区的时钟格式配置。
2. 擦除专用测试扇区 `0x0000F000..0x0000FFFF`。
3. 从扇区偏移 250 开始写入 32 字节，覆盖页边界，读回并校验整个 4 KiB 扇区。
4. 使用 4 KiB scratch 更新其中 8 字节，再次校验整个扇区。
5. 保存自检结果后持续处理配置请求和后台容量扫描；后续请求、扫描和恢复都不会再次擦除测试区。

该地址区只用于本自检和后续测试接口，当前没有为字库、图标、缓存或日志虚构布局。正常产品数据不得使用该区域。`storage_get_diagnostics()` 可读取保留的结果、ID 和状态寄存器。

配置 `ready` 在启动初始化及自检结束后才发布，显示首刷会等待这一终态；容量扫描在此后后台执行，不要求扫描全片才显示首屏。初始化或自检失败时发布相应故障，不能将首屏等待时间视为已经测得的固定值。

如需禁止破坏性启动自检，可在 Keil 工程定义中覆盖 `STORAGE_BOOT_TEST_ENABLE=0`；此时仍执行初始化和诊断，但测试状态为 skipped。

## 时钟格式配置

配置占用外部 Flash 最后两个独立的 4 KiB 扇区 `0x00FFE000..0x00FFEFFF` 和 `0x00FFF000..0x00FFFFFF`，与启动测试区互不重叠。每扇区首 24 字节保存小端记录：magic、版本、递增序号、12/24 小时格式、CRC32、提交标记，每项 4 字节。CRC32 使用标准反射多项式 `0xEDB88320`、初值及最终异或 `0xFFFFFFFF`，覆盖前 16 字节。

写配置时只擦除非活动扇区，写入并读回验证前 20 字节，再单独写入提交标记并验证完整记录。旧有效记录一直保留；不使用不具备掉电原子性的 `w25q128_update()`。所有设备调用各自加锁，事务层不再次取得非递归锁。启动选择序号最新的有效记录，比较支持 32 位序号回绕。一份记录有效时允许回退，另一份非空且损坏记入 `config_degraded` 诊断。

两个记录全空时使用 24 小时默认值。没有有效记录且存在损坏记录时，默认值仍可显示，并报告 STORAGE 的 CFG 错误。明确的格式写入请求可修复配置。写入出错后，下次请求先初始化和重新加载记录，避免实际提交成功但应答失败时使用过期活动扇区。启动自检失败保留 W25Q 故障到下次启动自检；配置写入成功不代表测试区域恢复。

`storage_get_config_snapshot()` 提供一致的格式、版本修订号、ready/busy 和异步完成 token/result。`storage_request_format(format, token)` 非阻塞，token 必须非零；返回 0 表示已受理，-1 参数错误，-2 正忙或启动未结束，-3 服务未创建。一个静态、深度为 1 的队列保证最多一个在途请求，不增加 RTOS 堆分配。完成后保存 token 和 0/负错误结果，后续完成会覆盖。只有启动加载或请求成功提交导致格式改变时才递增修订号。失败请求保留已经发布的格式和修订号，即使恢复读取发现上次应答失败的已提交记录，也只在后续请求成功时更新显示。故障、诊断和完成快照在同一个短临界区发布，所有 Flash 操作均在临界区外执行。创建失败也结束启动等待并保留默认格式。

串口 `FORMAT 12` / `FORMAT 24` 仅持久化显示格式。`TIME` 由时钟服务写 RTC，不写 W25Q；WEATHER 缓存和 PAGE 选择仅在 RAM。TIME 与 FORMAT 可以各有一个在途请求，互不占用对方的邮箱或队列；WEATHER 和 PAGE 也不受格式写入的忙状态阻塞。完整应答和退出控制台的忙规则见 [控制台协议](debug_console.md)，校时规则见 [校时协议](time_protocol.md)。

## 非空扇区容量

`storage_get_usage_snapshot()` 在短临界区内复制 RAM 快照，返回 `state`、
`used_bytes`、`total_bytes` 和独立的扫描错误 `result`，不访问 Flash，不等待扫描。
分母固定 16 MiB；全片 4096 个扇区中，任意字节不是 `0xFF` 的扇区均计入 4096 字节。
配置、自检、旧记录及部分写入的残留均计入；这是物理非空扇区容量，不是文件系统
已分配空间。有效数据中的全 `0xFF` 扇区无法通过此统计识别。

启动初始化和自检结束后开始首轮扫描，随后每轮成功或失败结束后等待 1 小时再扫。
周期按 RTOS tick 差值计算，支持 32 位回绕。每轮重新初始化计数；扫描以 256 字节
读入、逐 4 KiB 扇区推进，找到非空字节后跳过本扇区剩余页面。扫描循环等待 1 tick
让出执行权，每次最多处理一个配置请求后继续扫描，不要求显示任务发起 Flash IO。
当前唯一运行期写入区域是末尾两个配置扇区，它们在同一步连续读取并发布结果，
期间配置请求仍可入队，下一个循环处理。以后增加其他运行期写入区域时，必须同时
扩展这一一致性约束。外部烧录器不应与 MCU 同时驱动 SPI；离线改写后的内容会在
重启或下一轮扫描中反映。

未启动为 `UNAVAILABLE`；首次和周期扫描中为 `INITIALIZING`，轮到 W25Q 格时显示
`SCAN`；完整成功后为 `READY`，显示 `ceil(used_bytes * 100 / total_bytes)`，空片
`0%`、非空最低 `1%`、全满 `100%`。失败丢弃本轮计数并发布 `ERROR`、零 `used_bytes`
及实际错误码，正常格显示 `N/A`，同时通过既有 W25Q 来源报告 STORAGE 故障。
不改变原有 SRAM/IFLASH/W25Q 轮换与分钟刷新，也不因扫描进度额外刷新屏幕。

扫描错误、自检错误和配置错误聚合，恢复任意一项不会清除其他错误。扫描成功不会
绕过配置写入失败后的初始化和重新加载，扫描失败也不会重放写入或启动破坏性自检。
扫描使用现有读接口及超时；健康总线下普通扇区最多读 4 KiB，配置尾部最多读 8 KiB，
约 27/55 ms 纯传输时间。异常 WIP 或总线等待仍受现有驱动超时约束，不能保证相同
请求延迟。当前 SPI1 1.25 MHz 下，空片全扫的纯数据传输下限约 107 秒，实际包含命令、
状态检查和任务调度，会更长。没有为容量统计新增 Flash 写入、擦除或 RTOS 堆分配。

## 错误与恢复

返回值包括参数、范围、总线 IO、ID 不符、超时、忙、读回校验、保护和需要擦除等错误。传输失败时平台适配会释放 CS，并调用 `HAL_SPI_Abort()` 清理 SPI 状态；驱动不会自动重放可能已经到达 Flash 的破坏性命令。调用者应记录错误和地址，确认 WIP 已清除、保护状态正确后再决定是否重试。对更新失败尤其不能盲目重试，因为前一轮可能已经擦除扇区。
